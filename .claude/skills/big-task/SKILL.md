# big-task（大きな作業の段取り）

## 目的

大きな作業は、途中で止まります。会話が長くなって前半を忘れる、失敗が
静かに一部だけ通る、途中で方針が変わる。**止まることを前提に組めば、
止まっても続きから再開でき、失敗も見えます。**

## 呼ぶタイミング

- 対象を数えて5件以上あり、同じ手順で処理するとき
- 1回の会話では終わらない、何回かに分ける作業
- あなたに任せきりにして、最後まで進めてもらう作業
- 網羅的に集める・調べる作業
- 初めて取り組む種類の作業、元に戻せない変更を含む作業

## 呼ばない場面

- 決まった時刻に自動で動く処理 → `automation-setup`
- 新しいAI従業員を作る → `skill-writing`

---

## STEP 1　始める前に、見落としやすい点を出す

次のどれかに当たるときは、手を動かす前に3つを行います。

- 初めて触る種類の作業
- 何回かに分ける規模の作業
- 公開する・消す・大きな設計を決める作業
- ゴールを1文で言えない作業

1. 社長が見落としやすい点・危ない点・先に決めるべき分かれ道を、**短い一覧で**出す
2. そのうち「答えによって進め方が変わる問い」だけを、**1問ずつ**聞く（全部は聞かない）
3. 得た答えを、下の目標メモに書き込んでから始める

## STEP 2　目標メモを作り、進み具合を書き続ける

言われなくても、始める前に1つのファイルを作ってください。

```
目標：〈1文で〉
前提：〈社長と確かめたこと〉
参考にするもの：〈ファイル・資料〉
進み具合：〈どこまで済んだか〉
次にやること：〈 〉
つまずいているところ：〈 〉
```

進み具合は、**区切りごとに、その場で**書き換えます。会話が途中で切れても、
次のあなたがこのファイルから再開できます。

次のどれかに当たるときは、報告と同時に**引き継ぎメモ**も作ってください。

1. 終わらないまま中断する
2. 終わったが、次にやることが残っている
3. 次の会話でも続ける見込みがある

## STEP 3　5件以上なら、繰り返しの設計をしてから始める

件数が前もって分からないときは、対象の一覧を作った直後に数えてください。
5件以上なら、使い捨ての手順で走り始めないでください。途中で止まったときに
再開できず、失敗が静かに一部だけ通ります。

**任せきりにする前に、次の4つがそろっているかを確かめます。1つでも欠けたら、
任せきりにしないでください。**

1. **完了の条件を1文で書ける**（「全〇件が△△になったら完了」）
2. **失敗しても、被害が1件分で止まる**（元のデータを直接壊さない。元に戻せない
   操作は、まず1件だけ試して社長に見せる）
3. **1件ごとの合否を、機械で判定できる**（出力・応答・差分で見る。
   「目で見て確認」は判定の方法になりません）
4. **止める条件を、始める前に決めてある**（件数の上限・失敗の回数・時間の上限）

設計を社長に見せ、了承を得てから始めます。

**網羅的に集める作業**では、数える単位を「対象」ではなく
**「マス（対象 × 項目）」**にしてください。

- 「その対象を調べた」では終わりません。項目ごとに埋まっているかを見ます
- 完了は「作業を一通り回した」ではなく、**「まだ確かめていないマスがゼロ」**
- 「探したが無かった」には、**どこを探したかの一覧**を付けます（付けないと、
  調べていないのと見分けがつきません）
- 1つのマスに、入口が2つ以上ないかも考えます（1件見つけて終わりにしない）
- ほかのAIに手伝わせたら、返ってきた指摘の**全部に「採る／採らない／保留」を
  記録してください。** 黙って消さないでください

## STEP 4　進めているあいだに守ること

- 1件ずつ、**進み具合をその場でファイルに保存**してください（まとめて書かない）
- **証拠のない「済」を書かないでください。** 1件ごとの確かめた結果を残します
- 失敗したものは、記録して飛ばします。原因の調べものに深入りして、全体を
  止めないでください。まとめて最後に報告します
- 途中で、確かめ方や対象の範囲を変えたくなったら、**止まって社長に聞いてください。**
  黙って設計を変えないでください
- **続けて3回失敗したら、止めてください。** 1件ずつの問題ではなく、やり方その
  ものに問題がある可能性が高いからです

## STEP 5　道具の使い分け

- 重い判断・設計・大事な文章は、上位のモデルで行ってください。集める・整える・
  分類するといった決まった下処理は、軽いモデルに任せられます
  （Claude Code では `/model` で切り替えられます）。**ただし、費用を理由に、
  確かめる工程を省かないでください**
- 別のAI（サブエージェント）に確かめさせる設計にしているのに、呼び出せ
  なかったときは、**黙って自分で代わりにやらないでください。** 「呼び出せません
  でした」と社長に伝えます。自分の作業を自分で確かめると、甘くなるからです
- 会話の中身を消す操作（`/clear`）は、①関係の無い作業を始める ②同じ間違いを
  2回以上くり返した ③対象を取り違えたまま進めた、のときだけにしてください。
  時間がたったことを理由にしないでください。消す前に、いまの状態を
  目標メモに書いておきます

## STEP 6　複数の画面で、同時に作業しているとき

社長が Claude Code を複数の画面で同時に動かしていると、それぞれが同じ
ファイルを触ります。**自分が書いていない変更**を見つけたら、次の順で扱います。

1. だれ（どの画面）の変更かを確かめる
2. その画面がまだ作業中なら、**触らずに**社長に伝える
3. もう止まっている、またはだれのものか分からないなら、変更履歴（Git）に
   記録する。「別の画面の作業で、途中の可能性がある」と書き添える

**まだ記録していない変更が、いちばん壊れやすい状態です。** 迷ったら、
記録する側に倒してください。変更履歴を消すコマンド（`git reset --hard`・
`git clean` など）は、ほかの画面の作業ごと消すので、必ず社長の確認を取ります。

## 報告

`.claude/rules/completion.md` の形で報告し、次を添えてください。

- 件数の突き合わせ：受け取った件数＝済＋失敗＋飛ばした
- 失敗したものの内訳と、考えられる原因（同じ型が続くなら、根本の原因として扱う）
- 目標メモ・進み具合のファイルの場所
