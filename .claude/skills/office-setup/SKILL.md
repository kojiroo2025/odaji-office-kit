# office-setup（開設の進行役）

## 目的

AIオフィスの開設には、社長が決めることが多く含まれます。
**1回で終える社長もいれば、何回かに分ける社長もいます。何回に分けるかを、
あなたが決めないでください（2026-09-15・キットの作り手の判断）。**
このスキルは、**続けても、途中で止めて続きから再開しても、どちらでも進められる形**に
してあります。

開設が終われば、このスキルの出番はなくなります。

## 呼ぶタイミング

- オフィス開設キットを入れた直後
- 社長が「オフィス開設の続きをやりましょう」と言ったとき
- 社長が「まだ埋まっていないところを教えて」と聞いたとき

## 呼ばない場面

- 個々の仕事の手順書（スキル）を作るとき → `skill-writing`
- キットの新しいバージョンを確認するとき → `kit-update`
- 開設が終わったあとの通常の仕事

---

## STEP 1　いまの状態を数える

`SETUP_STATUS.md` があるか見ます。

**なければ、`START_HERE.md` の STEP 0 を読んで、そのとおりに判定してください。**
**ここで判定しないでください。** STEP 0 は3つに分けています
（直下にある／`AI_Office` という子フォルダの中にある／どちらでもない）。
**「なければ自作環境」と決めつけると、社長がフォルダを開き間違えたときに取り違えます。**

**あるのに中身が空のとき**は、各マスの状態を**実際に確かめて**記入します。
推測で「済」にしないでください。ファイルの内容を開いて、書かれているかどうかを見てください。

**あれば読みます。** ただし、前回から社長が手で直している可能性があるので、
「未」になっているマスだけは、もう一度実際に確かめてから進めます。

**そして「済」のマスも、そのまま信じないでください。**

**表は、前回のあなたが埋めたところまでしか映していません。**
**社長が答えた直後に Claude Code を閉じた場合、答えたのに「未」のままのことがあります。**
**逆に、社長が手でファイルを直していれば、「未」なのに済んでいることもあります。**

**再開のときは、表と実体を突き合わせてから始めてください。**

| 見るマス | 実体をどこで確かめるか |
|---|---|
| ①③④⑤⑥・⑬ | `CLAUDE.md` の該当の欄に、実際に文字が入っているか |
| ⑧⑨ | `SETUP_STATUS.md` のメモ欄に、社長に伝えた結果が書かれているか（⑧は外部サービスの禁止の名前が `.claude/settings.json` の `deny` にあるかも見る。削除の行は、社長が禁止を希望したときだけ足されるので、ないことは「未」の根拠にしない）。**メモ欄が空なら、伝えたかどうかは確かめられないので「未」のままにする** |
| ⑦ | `git log` が使えるか（⑦が「済」なら、控えが1つ以上あるはずです） |
| ② | `Shared_Assets/Company_Info.md` の該当の欄 |
| ⑩ | `CLAUDE.md` に、4つの共通資料をいつ参照するかの指示が書かれているか |
| ⑪ | `Shared_Assets/` の直下にロゴの画像があり、そのファイル名が `Shared_Assets/Design_Rules.md` に書かれているか（保留なら「保留にしたもの」の欄） |
| ⑫ | `Shared_Assets/Design_Rules.md` の「色」の欄 |
| ⑭⑮ | `.claude/settings.json` に `hooks` があるか |

**食い違いを見つけたら、表のほうを実体に合わせて直し、社長に1行で伝えてください。**

> 進捗の表では〈N〉が「未」でしたが、実際には終わっていました。表を直しました。

**これを飛ばすと、答えたことをもう一度聞くか、終わっていないマスを飛ばすかの
どちらかが起きます。** どちらも社長には見えません。

### 状態は3つだけ

| 状態 | 意味 |
|---|---|
| 済 | 記入・作成が終わっている |
| 保留 | 社長が「今は決めない」と判断した。**理由を1行残す** |
| 未 | まだ手をつけていない |

**「開設の日」と「続きの回」のマスの「未」がゼロになったら、開設は完了です。**
「使う場面が来たら」のマスは数えません。その場面が来たときに準備します。

### マスの一覧

マスの一覧は `SETUP_STATUS.md` にあります。**ここには書き写しません。**
一覧が2か所にあると、片方だけが直されて食い違うためです。

**すでにClaude Codeを使い込んでいる環境では、多くが最初から「済」になります。**
それでよいのです。**この一覧は、進捗を測るものであって、作らせるものではありません。**

## STEP 2　残りを社長に見せる

「未」と「保留」を一覧で示します。

そのうえで、こう伝えます。

> 【報告】
> README 第3部の〈番号〉「〈項目名〉」まで終わっています。
> 第3部の〈番号〉「〈項目名〉」から順に進めます。

**「どこまで進めますか」「全部ですか」と聞かないでください（2026-09-16・キットの作り手の指示）。**
社長は、このスキルを呼ぶ直前に、`START_HERE.md` の「このまま続けますか？」に答えているか、
「オフィス開設の続きをやりましょう」と言って、続けることをもう決めています。
同じことを重ねて聞くと、しつこく感じられます（実機テストでの指摘）。
**途中で区切るかどうかは、下の「社長が疲れてきたら止める」で聞きます。**

**番号と項目名は、README 第3部の13〜18の表の番号と言葉のまま使ってください**（`SETUP_STATUS.md` の番号と同じです）。13から始めるときは「README 第3部の1〜12が終わっています」と伝えます。
**「〈N〉/18」のような進捗の表の数え方と、かかる時間の見込みは、伝えないでください**（`START_HERE.md` 大原則②。2026-09-16・キットの作り手の判断）。

### ⑬から先に入るとき、1回だけ聞くこと

`SETUP_STATUS.md` の「使う場面が来たら」について、まだ一度も聞いていなければ
（「聞いた日」が空欄なら）、次の1問を添えます。

```
次の4つは、実際に使うときに準備すれば間に合います。
使う日が近いものは、いま準備しておくと、その日に作業が中断しません。
いま準備したいものがあれば番号で（いくつでも）、なければ「なし」とお答えください。

（1）請求書・見積書（インボイスの登録番号、支払いの条件、ファイルのテンプレート）
　　 登録番号や振込先は変わらない情報なので、いつ準備しても無駄になりません。
（2）資料の作り方（文字の大きさ、見出しの付け方、余白、ロゴを置く位置）
　　 実際に資料を1つ作ってから決めるほうが、やり直しが少なくて済みます。
（3）お使いのソフトやサービス（会計ソフトなど）
　　 つなぐ予定があるときに準備します。
（4）社長の文章のくせ（私が書く文章を、社長らしい文章にするためのもの）
　　 私の文章を何回か直していただいてからのほうが、正確に集められます。
```

答えを「聞いた日」と「選ばれたもの」に書き、選ばれたマスはこの回の作業に加えます。
選ばれなかったものは、社長が言わない限り、その場面が来るまで進めません。

## STEP 3　1つずつ埋める

社長が選んだマス、または上から順に、**1つずつ**進めます。

> **⑯⑰⑱は、番号順に進めてください。**
> **⑯（鍵の隔離）→ ⑰（バックアップを作る）→ ⑱（戻せることの確認）**です。
> **入れ替えないでください。理由は STEP 6 に書いてあります。**
> （2026-09-15に番号を付け替え、進める順と番号の順を揃えました）

### 守ること

- **質問は `.claude/rules/work-style.md` の「社長に質問するときの書き方」に従う。**
  何について聞くのか・答えを何に使うのか・どう答えればよいのか、の3つを入れる
- **1回に複数のマスを聞かない。** 1つ終わってから次を出す
- **社長が答えられないときは「保留」にして、理由を1行書いて次へ進む。**
  推測で埋めない。空欄のまま残すのは構わない
- **技術の説明を並べない。** 社長が判断するのに必要な材料だけを出す。
  「〈A〉にすると〈こうなります〉。〈B〉にすると〈こうなります〉。おすすめは〈A〉です」
- **1マス終わるごとに `SETUP_STATUS.md` を書き換える。** まとめて書かない。
  途中で中断しても、書いたところまでは残ります
- **1マス終わるごとに、下の文で報告し、次へ進んでよいかを聞いて、返事を待つ（2026-09-16・キットの作り手の指示）。**
  返事を待たずに次のマスへ進まないでください（実機テストで、⑬の直後に確認なしで⑭⑮へ進んだ）。
  **⑭と⑮（フック2つ）だけは、まとめて1回の報告にして構いません。**

> 【報告】
> README 第3部の〈番号〉「〈項目名〉」が終わりました。
> 次は、第3部の〈番号〉「〈項目名〉」です。
> 次の手順に進んでよろしいですか？

  「ここで中断します」と言われたら、そこで終わります。

### 聞き方の見本（大切にしていること）

```
会社として大切にしていること（経営理念、ミッション、ビジョンなど）を、1つか2つ教えてください。
私が仕事の中で判断に迷ったとき、判断のよりどころにします。
（例：お客様に説明できないことはしない／無理な注文は受けない）
会社のホームページに経営理念などを載せたページがあれば、
そのページのURLを教えていただくだけでも構いません。私が読み取って、内容を確認していただきます。
すぐに思い浮かばなければ、今回は飛ばして構いません。
```

答えは、`CLAUDE.md` と `Shared_Assets/Company_Info.md` の「大切にしていること」の
両方に書きます。

**`CLAUDE.md` にその欄がないとき**（社長が比較のときに「入れない」と決められた場合）は、
**`Shared_Assets/Company_Info.md` の側にだけ書いて、先へ進んでください。**
**止まらないでください。** 書かなかったことは、社長に1行伝えます
（書き方は `START_HERE.md` の「すでに作ってある環境に入れるとき」にあります）。

### 社長が疲れてきたら止める

1マスごとに「次の手順に進んでよろしいですか？」と聞いているので、ほかに区切りの質問を足す必要はありません。
社長の返事が短くなってきた、答えに迷いが見えるときは、その報告の文の最後を
「続けますか、ここで中断しますか。」に替えて構いません。

**急かさないでください。** ここで無理に進めると、あとで作り直すことになります。

## STEP 4　確かめる（省かない）

次の3つは、**作っただけで終わらせず、実際に動くところを見てください。**

| 何を | どう確かめるか |
|---|---|
| 禁止事項（deny） | **社長に見せる工程は、2026-09-15に外しました。** 拒否されたとしても示せるのは「その命令が拒否される」ことだけで、**同じことができる別の命令が残ります。**「もう安全だ」と受け取られるので、かえって危険です。**あなた自身が書式の誤りを確かめるのは構いません**（`settings.json` が読めなくなっていないか）。社長へは、足した事実と「それでも100%ではない」ことを伝えます |
| 変更履歴のフック | テスト用のファイルを作って変更し、記録が自動で残るか見る。**終わったら、テスト用ファイルの名前を社長に伝える**（削除を禁止していれば、あなたには消せません。それが正しい状態です）。**これは STEP 5 でフックを作ったあとに行います。**STEP 5 より前には、確かめる対象がありません |
| バックアップ | 実際に走らせ、**戻せることまで**確かめる（保存されただけでは保険になりません）。**これは STEP 6 で⑰を作ったあとに行います。**⑰より前には、確かめる対象がありません |

もっともらしい設定と、本当に効いている設定は別物で、実行しないと区別できません。
**効いていない設定は、効いているつもりでいる分だけ、ないより危険です。**

この考え方の出どころは `.claude/rules/safety.md`「設定を変えたら、必ず効いていることを確かめる」にあります（ここには書き写しません）。

## STEP 5　フックを2つ作る（キットには入っていません）

フックはこのバージョンのキットに入っていません（技術的には持ち運べますが、環境によって
挙動が変わるため、まだ確かめ切れていません）。この環境に合わせて作ります。

1. **作業の区切りで、Gitに変更履歴を記録する**
2. **CLAUDE.md が200行に近づいたら知らせる**

どちらも、設定する前に内容と影響を社長に説明し、確認を得てください。
作ったら STEP 4 のとおり動作を確かめてください。

### どこに、どう作るか

**書き込む先は `.claude/settings.json` の `hooks` です。**
`.claude/settings.json` には、いま `permissions` だけが入っています。
**そこへ `hooks` を足します。permissions の中身は消さないでください。**

**`.claude/settings.json` がそもそもないときは、新しく作って構いません**（`hooks` だけの
中身で始めます）。**社長に「作ってよいか」を聞く必要はありません。**
**ただし、もし社長が比較のときに「禁止事項は入れない」と決められていたなら、
そちらは足さないでください。** 決められたことを、こちらから覆さないためです。

**書き方は、お使いのバージョンによって変わります。** 公式ドキュメントで確かめてから書いてください。

```
https://code.claude.com/docs/en/hooks-guide
```

**確かめずに書かないでください。** 書式が違うと、**設定ファイル全体が読まれなくなり、
いま効いている禁止事項まで効かなくなります。**

**Windows では、フックのコマンドに書くパスを `/` で書いてください**（例：`C:/AI_Office/Programs/...`）。
`\` で書くと、`Git`（Git Bash）の入ったパソコンではフックが Bash を通して実行されて `\` が取り除かれ、
フックが失敗します。**その失敗は画面に何も出ません**（2026-09-19に、キットの制作時に実測）。
**作ったら、STEP 4 のとおり、実際に動いたことまで確かめてください。** 書いただけでは、動いたかどうか分かりません。

**確かめ方は `.claude/skills/fact-check/` に従ってください。** ここでの要点は3つです。

- **上のページの本文を、実際に取って読んでください。**
  検索結果の抜粋や、自分の記憶で書かないでください
- **取れなかったときは、書かないでください。**
  社長にこう伝えます＝「フックの書き方を確かめる公式のページが読めませんでした。
  推測で書くと、いま効いている禁止事項まで効かなくなる可能性があります。ここは作らずに残します」
- **⑭⑮は「保留」＋理由で構いません。** 保留は失敗ではありません。
  **確かめずに書いて壊すことのほうが、はるかに重い**です

### 「済」にしてよい条件

**作っただけでは「済」にしません。** 次の両方を満たしたときだけです。

| マス | 済にしてよい条件 |
|---|---|
| ⑭ | ファイルを1つ変えて、**記録が自動で残ったことを社長に見せた** |
| ⑮ | `CLAUDE.md` を一時的に長くして、**知らせが出たことを社長に見せた**（見せたら元に戻す） |

**動かして見せられなかったときは「保留」＋理由**にしてください。

**なぜフックにするのか**：「区切りで変更履歴に記録してよい」と許可しただけでは、
記録は実行されません。許可と実行は別物です。**必ず行う工程**にするために、
フックにします。

変更履歴に記録するときのルール：

- 変えたファイルを**名指しで**記録します。全部をまとめて記録する指定
  （`git add -A` など）は使わないでください。ほかの画面の書きかけの作業まで
  巻き込みます
- **1つの直しを、1回の記録**にします。あとで1か所だけ元に戻したいとき、
  記録の単位と直しの単位がそろっていないと戻せません

**壊れたときの戻し方のメモは、AIオフィスの外にも置いてください**
（別のフォルダ、印刷して手元に、など）。AIオフィスが壊れたとき、
その中にある戻し方のメモは読めません。

## STEP 6　火災保険の残りを片づける（⑯ → ⑰ → ⑱ の順）

**この3つは、フックとは別です。** そして**順番が決まっています。番号のとおりです。**

> **⑯（鍵の移動）→ ⑰（バックアップを作る）→ ⑱（戻せることの確認）**

- **⑯を先にやる理由**：鍵がAIオフィスの中にあるままバックアップを作ると、
  **鍵も一緒にバックアップの保存先へ複製されます。** 過去の世代を残す方式
  （第9号の方式）では、**鍵が過去のバックアップに残り、すぐには削除できません**
- **⑰を⑱より先にやる理由**：バックアップがなければ、戻せるかを確かめられません

### ⑯の前に　フォルダの権限を、社長のアカウントだけに絞る（Windows・Mac とも）

**AIオフィスと、鍵を保管する専用フォルダは、社長のアカウントだけが開ける状態にします。**
パソコンにほかのアカウント（家族・従業員・以前の利用者）があると、既定の権限では、
そのアカウントが鍵を読んだり、1時間ごとに社長のアカウントで動くバックアップのプログラムや
`CLAUDE.md`・`.claude/settings.json` を書き換えたりできることがあります。

**対象のフォルダ**：①AIオフィス ②鍵を保管する専用フォルダ（⑯で新しく作るとき・第9号の手順で作ったものを使うとき・
あとから作るとき。**作るたび、使い始めるたびに、この手順を行います**）。以下の〈フォルダ〉は、実際の場所に置き換えます。

**要るかどうか**：Windows で〈フォルダ〉が利用者のフォルダ（`C:\Users\〈名前〉\…`）の中にあるときは、既定で本人だけに
絞られているので要りません。それ以外（`C:\AI_Office` のような Cドライブの直下・ほかのドライブ・`C:\Work\…` など）は行います。
Mac は、どこにあっても行います。

1. **社長に1行で伝え、承認を得ます。**
   ```
   このパソコンのほかのアカウントから、AIオフィス（と鍵のフォルダ）を開けないように、権限を社長のアカウントだけに絞ります。
   このパソコンをほかの方と共用していて、その方が AIオフィスのファイルを使っている場合は、その方は開けなくなります。よろしいですか。
   ```
   社長が「ほかの方も使っている」とおっしゃったら、実行せずに、どうするかを聞きます
2. **実行します。** Windows は、**PowerShell の1回の呼び出しで、次の1行を**実行します
   （Bash では実行しません。行を分けると、社長のアカウントの名前が空になります）。
   ```
   icacls "〈フォルダ〉" /inheritance:r /grant:r "$(whoami):(OI)(CI)F" "*S-1-5-18:(OI)(CI)F" "*S-1-5-32-544:(OI)(CI)F"
   ```

   （社長本人・SYSTEM・Administrators だけに、フォルダの中のファイルも含めて権限を与え、ほかの権限を外します）
   Mac は、ターミナルで次の1行を実行します。
   ```
   chmod 700 "〈フォルダ〉"
   ```
3. **確かめます。** Windows は `icacls "〈フォルダ〉"` の表示に、社長のアカウントの名前があり、
   `Authenticated Users`・`Users`・`Everyone` がないこと。Mac は `ls -ld "〈フォルダ〉"` の表示が `drwx------` で始まること
4. **確かめられなかったとき・エラーになったとき**は、次へ進まずに、表示された文言をそのまま社長に伝えます

   社長のアカウントが開けなくなったときは、Windows は `icacls "〈フォルダ〉" /reset /T`（Mac は `chmod 755 "〈フォルダ〉"`）で元の権限に戻せます
5. 済んだら、⑯のメモ欄に「権限を絞ったフォルダ」を書きます

#### 3. プログラムを書く（仕様）

`Programs/backup/backup_to_onedrive.ps1` を作ります。**次の仕様を1つも省かないでください。**

| 項目 | 仕様 | 理由 |
|---|---|---|
| 写し方 | `robocopy 〈AIオフィス〉 〈OneDrive〉\AI_Office_Backup /E` | `/E`＝下の階層も含めて写す。**`/MIR` と `/PURGE` を付けないので、写しの側では消えない**（この2つは付けない） |
| 写さないフォルダ | `/XD .git` と、社長が2で外したフォルダ | Microsoft の注意（上）。社長の判断 |
| 写さないファイル | `/XF .env .env.* *.env *.pem *.key *.p12 *.pfx *credential* *token*.json *secret*.json *.tmp ~$* backup_log.txt last_success.txt` | 鍵を写さない（`.claude/settings.json` の `Read(...)` と同じ形）。`*.env` を落とすと、鍵がクラウドへ写ります（2026-09-19に、キットの制作時に実測） |
| 再試行 | `/R:1 /W:1` | 既定では、開けないファイルが1つあると、ほぼ止まり続けます（既定は100万回・30秒間隔） |
| 記録 | `/NP /LOG+:〈AIオフィス〉\Programs\backup\backup_log.txt`。**実行の前に、ログが1MBを超えていたら、古い分を消して最後の200行だけ残す** | 何が起きたかを後から見るため。追記だけだと際限なく大きくなります |
| 成功の判定 | **終了コードが8未満なら成功、8以上なら失敗**（Microsoft の公式の定義） | 0〜7 は「写した・変更なし」などの成功 |
| 成功したとき | `Programs\backup\last_success.txt` に、成功した日時を `yyyy-MM-dd HH:mm:ss` の形で1行だけ書く（上書き） | 見張り（下の5）が読みます |
| 失敗したとき | `last_success.txt` を書き換えない。ログに終了コードを残す | 古い日時が残ることで、見張りが気づきます |
| 場所の書き方 | OneDrive の場所は、**プログラムの中で環境変数 `$env:OneDrive` から組み立てる**（ユーザー名が日本語のこともあるため、文字で書かない）。パスは変数で `robocopy` に渡し、**末尾に `\` を付けない** | `robocopy "C:\x\"` のように末尾が `\` だと、引用符と組み合わさって引数が崩れます |
| 文字 | **プログラムの中に日本語を書かないでください** | Windows の PowerShell 5.1 は、BOM のない UTF-8 のファイルの日本語を読み違えます（2026-09-19に、キットの制作時に実測） |

**AIオフィスの場所そのものが日本語を含むときは**、プログラムを BOM 付きの UTF-8 で保存します
（保存のしかたは下の5の「文字」の行と同じです）。

#### 4. 1時間ごとに動かす

Windows のタスクスケジューラに、**PowerShell の `Register-ScheduledTask` で**登録します（管理者権限は要りません）。

**登録の前に、AIオフィスに「⑯の前に　フォルダの権限を、社長のアカウントだけに絞る」が済んでいることを確かめます**
（⑯のメモ欄）。済んでいなければ、先に行います。1時間ごとに社長のアカウントで動くプログラムを、ほかのアカウントに
書き換えられないようにするためです。

```
$a = New-ScheduledTaskAction -Execute 'conhost.exe' -Argument '--headless powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:/AI_Office/Programs/backup/backup_to_onedrive.ps1"'
$t = New-ScheduledTaskTrigger -Once -At (Get-Date).AddMinutes(5) -RepetitionInterval (New-TimeSpan -Hours 1)
$s = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries -StartWhenAvailable -ExecutionTimeLimit (New-TimeSpan -Minutes 30)
Register-ScheduledTask -TaskName 'AI_Office_Backup' -Action $a -Trigger $t -Settings $s
```

- **`schtasks /Create` は使わないでください。** 既定で「電池で動いているときは起動しない」設定になり、
  ノートパソコンでは写しが止まります（2026-09-19に、キットの制作時に実測）。上の設定は、
  電池でも動かし、パソコンが眠っていて起動し損ねた回を、起きたときに実行します
- 動くのは、社長がパソコンにサインインしているあいだです
- **`conhost.exe --headless` を必ず付けてください。** 付けないと、1時間ごとに黒い画面が一瞬出ます
  （`-WindowStyle Hidden` だけでは出ます。2026-09-19に、キットの制作時に実測）。社長が驚いて閉じると、写しが止まります
- パスは `C:/AI_Office/...` のように `/` で書きます。**`C:/AI_Office` は、実際のAIオフィスの場所に置き換えてください**。
  場所に空白を含むときも、上のとおり `"` で囲めば崩れません
- 登録したら、**`Start-ScheduledTask -TaskName 'AI_Office_Backup'` で1回動かし**（タスクスケジューラの経路で動くことを
  確かめるため。あなたがプログラムを直接実行して確かめたことにしないでください）、`last_success.txt` に日時が
  書かれたこと、`〈OneDrive〉\AI_Office_Backup` にファイルがあることを確かめます

| 項目 | 仕様 |
|---|---|
| 読むもの | `Programs\backup\last_success.txt` |
| 24時間以内 | 何も出力しないか、「バックアップは正常です（最後の成功：〈日時〉）」と1行出す |
| 24時間を超えた・ファイルがない | **その場で `backup_to_onedrive.ps1` を1回動かし、もう一度 `last_success.txt` を読む。** 成功していれば「バックアップは正常です」とだけ出す（週末にパソコンを閉じていただけで警告を出さないため）。それでも失敗なら「【バックアップの警告】AIオフィスのバックアップが、〈N〉時間成功していません（最後の成功：〈日時〉。いま実行した結果：終了コード〈N〉）。社長に、最初にこのことを伝えてください。」と出す |
| 文字 | 警告の文は日本語なので、**このファイルは BOM 付きの UTF-8 で保存する**。Write ツールは BOM を付けないので、書いたあとに PowerShell で `$p='〈ファイルの場所〉'; [IO.File]::WriteAllText($p, [IO.File]::ReadAllText($p), (New-Object System.Text.UTF8Encoding $true))` を実行して付け直す。先頭で `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` を実行する |
| 登録のコマンド | `powershell -NoProfile -ExecutionPolicy Bypass -File "C:/AI_Office/Programs/backup/check_backup.ps1"`（場所に空白を含んでも崩れないよう、パスを `"` で囲む。settings.json の中では `\"` と書く） |

**フックのコマンドのパスは、必ず `/` で書いてください。** `\` で書くと、`Git`（Git Bash）の入ったパソコンでは
`\` が取り除かれ、フックが失敗します。**しかも、その失敗は画面に何も出ません**（2026-09-19に、キットの制作時に実測）。

**セッションの最初に警告が届いたら**：社長への最初の返事で伝えます。原因を調べてよいかを聞き、
承認されたら、`backup_log.txt` と、タスクスケジューラの状態と、OneDrive の状態を見ます。

**作ったら、Claude に届くことまで確かめてください。**
1. `last_success.txt` の日時を、一時的に2日前に書き換え、**タスクを一時的に止めておく**
   （`Disable-ScheduledTask -TaskName 'AI_Office_Backup'`）。さらに、見張りがその場で動かす写しが失敗するよう、
   一時的に `backup_to_onedrive.ps1` の名前を `backup_to_onedrive.ps1.test` に変える
2. 社長に、新しいセッションを開いて「こんにちは」と送っていただく
3. 最初の返事に警告が出たことを、社長と一緒に確かめる
4. **元に戻す**：プログラムの名前を戻し、`Enable-ScheduledTask -TaskName 'AI_Office_Backup'` を実行し、
   `Start-ScheduledTask` で1回動かして `last_success.txt` が正しい日時に戻ったことを確かめる

## すでに環境がある社長への対応（差分検証）

**別の手順を用意していません。上と同じ STEP 1 から始めてください。**

STEP 1 で数えると、多くのマスが最初から「済」になります。そのうえで、
STEP 2 で残りを見せるときに、**もう1つの一覧**を添えてください。

> **このキットにあって、お手元にないもの**

具体的には、`.claude/rules/` の3ファイルと、このキットのスキルに書かれている
ルールを、社長の環境の同じ場所と比較します。違いがあれば、
**1件ずつ「何が違うか」「入れると何が変わるか」**を書いて示します。

**勝手に入れないでください。** 1件ずつ社長の承認を取ります。
社長が「要らない」と言ったものは、それで終わりです。理由を聞き返さないでください。
