# office-setup（開設の進行役）

## 目的

AIオフィスの開設には、社長が決めることが多く含まれます。
**1回で終える社長もいれば、何回かに分ける社長もいます。何回に分けるかを、
あなたが決めないでください（2026-09-15・耕治さんの判断）。**
このスキルは、**続けても、途中で止めて続きから再開しても、どちらでも進められる形**に
してあります。

開設が終われば、このスキルの出番はなくなります。

## 呼ぶタイミング

- オフィス開設キットを入れた直後
- 社長が「オフィス開設の続きをやりましょう」と言ったとき
- 社長が「まだ埋まっていないところを教えて」と聞いたとき

## 呼ばない場面

- 個々の仕事の手順書（スキル）を作るとき → `skill-writing`
- キットの新しいバージョンを確認するとき → `kit-update`
- 開設が終わったあとの通常の仕事

---

## STEP 1　いまの状態を数える

`SETUP_STATUS.md` があるか見ます。

**なければ、`START_HERE.md` の STEP 0 を読んで、そのとおりに判定してください。**
**ここで判定しないでください。** STEP 0 は3つに分けています
（直下にある／`AI_Office` という子フォルダの中にある／どちらでもない）。
**「なければ自作環境」と決めつけると、社長がフォルダを開き間違えたときに取り違えます。**

**あるのに中身が空のとき**は、各マスの状態を**実際に確かめて**記入します。
推測で「済」にしないでください。ファイルの内容を開いて、書かれているかどうかを見てください。

**あれば読みます。** ただし、前回から社長が手で直している可能性があるので、
「未」になっているマスだけは、もう一度実際に確かめてから進めます。

**そして「済」のマスも、そのまま信じないでください。**

**表は、前回のあなたが埋めたところまでしか映していません。**
**社長が答えた直後に Claude Code を閉じた場合、答えたのに「未」のままのことがあります。**
**逆に、社長が手でファイルを直していれば、「未」なのに済んでいることもあります。**

**再開のときは、表と実体を突き合わせてから始めてください。**

| 見るマス | 実体をどこで確かめるか |
|---|---|
| ①③④⑤⑥・⑬ | `CLAUDE.md` の該当の欄に、実際に文字が入っているか |
| ⑧⑨ | `.claude/settings.json` の `deny` に、削除の行が足されているか |
| ⑦ | `git log` が使えるか（⑦が「済」なら、控えが1つ以上あるはずです） |
| ②⑩⑫ | `Shared_Assets/Company_Info.md` の該当の欄 |
| ⑭⑮ | `.claude/settings.json` に `hooks` があるか |

**食い違いを見つけたら、表のほうを実体に合わせて直し、社長に1行で伝えてください。**

> 進捗の表では〈N〉が「未」でしたが、実際には終わっていました。表を直しました。

**これを飛ばすと、答えたことをもう一度聞くか、終わっていないマスを飛ばすかの
どちらかが起きます。** どちらも社長には見えません。

### 状態は3つだけ

| 状態 | 意味 |
|---|---|
| 済 | 記入・作成が終わっている |
| 保留 | 社長が「今は決めない」と判断した。**理由を1行残す** |
| 未 | まだ手をつけていない |

**「開設の日」と「続きの回」のマスの「未」がゼロになったら、開設は完了です。**
「使う場面が来たら」のマスは数えません。その場面が来たときに準備します。

### マスの一覧

マスの一覧は `SETUP_STATUS.md` にあります。**ここには書き写しません。**
一覧が2か所にあると、片方だけが直されて食い違うためです。

**すでにClaude Codeを使い込んでいる環境では、多くが最初から「済」になります。**
それでよいのです。**この一覧は、進捗を測るものであって、作らせるものではありません。**

## STEP 2　残りを社長に見せる

「未」と「保留」を一覧で示します。

そのうえで、こう伝えます。

> 【報告】
> README 第3部の〈番号〉「〈項目名〉」まで終わっています。
> 第3部の〈番号〉「〈項目名〉」から順に進めます。

**「どこまで進めますか」「全部ですか」と聞かないでください（2026-09-16・耕治さんの指示）。**
社長は、このスキルを呼ぶ直前に、`START_HERE.md` の「このまま続けますか？」に答えているか、
「オフィス開設の続きをやりましょう」と言って、続けることをもう決めています。
同じことを重ねて聞くと、しつこく感じられます（実機テストでの指摘）。
**途中で区切るかどうかは、下の「社長が疲れてきたら止める」で聞きます。**

**番号と項目名は、README 第3部の13〜18の表の番号と言葉のまま使ってください**（`SETUP_STATUS.md` の番号と同じです）。13から始めるときは「README 第3部の1〜12が終わっています」と伝えます。
**「〈N〉/18」のような進捗の表の数え方と、かかる時間の見込みは、伝えないでください**（`START_HERE.md` 大原則②。2026-09-16・耕治さんの判断）。

### ⑬から先に入るとき、1回だけ聞くこと

`SETUP_STATUS.md` の「使う場面が来たら」について、まだ一度も聞いていなければ
（「聞いた日」が空欄なら）、次の1問を添えます。

```
次の4つは、実際に使うときに準備すれば間に合います。
使う日が近いものは、いま準備しておくと、その日に作業が中断しません。
いま準備したいものがあれば番号で（いくつでも）、なければ「なし」とお答えください。

（1）請求書・見積書（インボイスの登録番号、支払いの条件、ファイルのテンプレート）
　　 登録番号や振込先は変わらない情報なので、いつ準備しても無駄になりません。
（2）資料の作り方（文字の大きさ、見出しの付け方、余白、ロゴを置く位置）
　　 実際に資料を1つ作ってから決めるほうが、やり直しが少なくて済みます。
（3）お使いのソフトやサービス（会計ソフトなど）
　　 つなぐ予定があるときに準備します。
（4）社長の文章のくせ（私が書く文章を、社長らしい文章にするためのもの）
　　 私の文章を何回か直していただいてからのほうが、正確に集められます。
```

答えを「聞いた日」と「選ばれたもの」に書き、選ばれたマスはこの回の作業に加えます。
選ばれなかったものは、社長が言わない限り、その場面が来るまで進めません。

## STEP 3　1つずつ埋める

社長が選んだマス、または上から順に、**1つずつ**進めます。

> **⑯⑰⑱は、番号順に進めてください。**
> **⑯（鍵の隔離）→ ⑰（バックアップを作る）→ ⑱（戻せることの確認）**です。
> **入れ替えないでください。理由は STEP 6 に書いてあります。**
> （2026-09-15に番号を付け替え、進める順と番号の順を揃えました）

### 守ること

- **質問は `.claude/rules/work-style.md` の「社長に質問するときの書き方」に従う。**
  何について聞くのか・答えを何に使うのか・どう答えればよいのか、の3つを入れる
- **1回に複数のマスを聞かない。** 1つ終わってから次を出す
- **社長が答えられないときは「保留」にして、理由を1行書いて次へ進む。**
  推測で埋めない。空欄のまま残すのは構わない
- **技術の説明を並べない。** 社長が判断するのに必要な材料だけを出す。
  「〈A〉にすると〈こうなります〉。〈B〉にすると〈こうなります〉。おすすめは〈A〉です」
- **1マス終わるごとに `SETUP_STATUS.md` を書き換える。** まとめて書かない。
  途中で中断しても、書いたところまでは残ります
- **1マス終わるごとに、下の文で報告し、次へ進んでよいかを聞いて、返事を待つ（2026-09-16・耕治さんの指示）。**
  返事を待たずに次のマスへ進まないでください（実機テストで、⑬の直後に確認なしで⑭⑮へ進んだ）。
  **⑭と⑮（フック2つ）だけは、まとめて1回の報告にして構いません。**

> 【報告】
> README 第3部の〈番号〉「〈項目名〉」が終わりました。
> 次は、第3部の〈番号〉「〈項目名〉」です。
> 次の手順に進んでよろしいですか？

  「ここで中断します」と言われたら、そこで終わります。

### 聞き方の見本（大切にしていること）

```
会社として大切にしていること（経営理念、ミッション、ビジョンなど）を、1つか2つ教えてください。
私が仕事の中で判断に迷ったとき、判断のよりどころにします。
（例：お客様に説明できないことはしない／無理な注文は受けない）
会社のホームページに経営理念などを載せたページがあれば、
そのページのURLを教えていただくだけでも構いません。私が読み取って、内容を確認していただきます。
すぐに思い浮かばなければ、今回は飛ばして構いません。
```

答えは、`CLAUDE.md` と `Shared_Assets/Company_Info.md` の「大切にしていること」の
両方に書きます。

**`CLAUDE.md` にその欄がないとき**（社長が比較のときに「入れない」と決められた場合）は、
**`Shared_Assets/Company_Info.md` の側にだけ書いて、先へ進んでください。**
**止まらないでください。** 書かなかったことは、社長に1行伝えます
（書き方は `START_HERE.md` の「すでに作ってある環境に入れるとき」にあります）。

### 社長が疲れてきたら止める

1マスごとに「次の手順に進んでよろしいですか？」と聞いているので、ほかに区切りの質問を足す必要はありません。
社長の返事が短くなってきた、答えに迷いが見えるときは、その報告の文の最後を
「続けますか、ここで中断しますか。」に替えて構いません。

**急かさないでください。** ここで無理に進めると、あとで作り直すことになります。

## STEP 4　確かめる（省かない）

次の3つは、**作っただけで終わらせず、実際に動くところを見てください。**

| 何を | どう確かめるか |
|---|---|
| 禁止事項（deny） | **社長に見せる工程は、2026-09-15に外しました。** 拒否されたとしても示せるのは「その命令が拒否される」ことだけで、**同じことができる別の命令が残ります。**「もう安全だ」と受け取られるので、かえって危険です。**あなた自身が書式の誤りを確かめるのは構いません**（`settings.json` が読めなくなっていないか）。社長へは、足した事実と「それでも100%ではない」ことを伝えます |
| 変更履歴のフック | テスト用のファイルを作って変更し、記録が自動で残るか見る。**終わったら、テスト用ファイルの名前を社長に伝える**（削除を禁止していれば、あなたには消せません。それが正しい状態です）。**これは STEP 5 でフックを作ったあとに行います。**STEP 5 より前には、確かめる対象がありません |
| バックアップ | 実際に走らせ、**戻せることまで**確かめる（保存されただけでは保険になりません）。**これは STEP 6 で⑰を作ったあとに行います。**⑰より前には、確かめる対象がありません |

もっともらしい設定と、本当に効いている設定は別物で、実行しないと区別できません。
**効いていない設定は、効いているつもりでいる分だけ、ないより危険です。**

この考え方の出どころは `.claude/rules/safety.md`「設定を変えたら、必ず効いていることを確かめる」にあります（ここには書き写しません）。

## STEP 5　フックを2つ作る（キットには入っていません）

フックはこのバージョンのキットに入っていません（技術的には持ち運べますが、環境によって
挙動が変わるため、まだ確かめ切れていません）。この環境に合わせて作ります。

1. **作業の区切りで、Gitに変更履歴を記録する**
2. **CLAUDE.md が200行に近づいたら知らせる**

どちらも、設定する前に内容と影響を社長に説明し、確認を得てください。
作ったら STEP 4 のとおり動作を確かめてください。

### どこに、どう作るか

**書き込む先は `.claude/settings.json` の `hooks` です。**
`.claude/settings.json` には、いま `permissions` だけが入っています。
**そこへ `hooks` を足します。permissions の中身は消さないでください。**

**`.claude/settings.json` がそもそもないときは、新しく作って構いません**（`hooks` だけの
中身で始めます）。**社長に「作ってよいか」を聞く必要はありません。**
**ただし、もし社長が比較のときに「禁止事項は入れない」と決められていたなら、
そちらは足さないでください。** 決められたことを、こちらから覆さないためです。

**書き方は、お使いのバージョンによって変わります。** 公式ドキュメントで確かめてから書いてください。

```
https://code.claude.com/docs/en/hooks-guide
```

**確かめずに書かないでください。** 書式が違うと、**設定ファイル全体が読まれなくなり、
いま効いている禁止事項まで効かなくなります。**

**確かめ方は `.claude/skills/fact-check/` に従ってください。** ここでの要点は3つです。

- **上のページの本文を、実際に取って読んでください。**
  検索結果の抜粋や、自分の記憶で書かないでください
- **取れなかったときは、書かないでください。**
  社長にこう伝えます＝「フックの書き方を確かめる公式のページが読めませんでした。
  推測で書くと、いま効いている禁止事項まで効かなくなる可能性があります。ここは作らずに残します」
- **⑭⑮は「保留」＋理由で構いません。** 保留は失敗ではありません。
  **確かめずに書いて壊すことのほうが、はるかに重い**です

### 「済」にしてよい条件

**作っただけでは「済」にしません。** 次の両方を満たしたときだけです。

| マス | 済にしてよい条件 |
|---|---|
| ⑭ | ファイルを1つ変えて、**記録が自動で残ったことを社長に見せた** |
| ⑮ | `CLAUDE.md` を一時的に長くして、**知らせが出たことを社長に見せた**（見せたら元に戻す） |

**動かして見せられなかったときは「保留」＋理由**にしてください。

**なぜフックにするのか**：「区切りで変更履歴に記録してよい」と許可しただけでは、
記録は実行されません。許可と実行は別物です。**必ず行う工程**にするために、
フックにします。

変更履歴に記録するときの決まり：

- 変えたファイルを**名指しで**記録します。全部をまとめて記録する指定
  （`git add -A` など）は使わないでください。ほかの画面の書きかけの作業まで
  巻き込みます
- **1つの直しを、1回の記録**にします。あとで1か所だけ元に戻したいとき、
  記録の単位と直しの単位がそろっていないと戻せません

**壊れたときの戻し方のメモは、AIオフィスの外にも置いてください**
（別のフォルダ、印刷して手元に、など）。AIオフィスが壊れたとき、
その中にある戻し方のメモは読めません。

## STEP 6　火災保険の残りを片づける（⑯ → ⑰ → ⑱ の順）

**この3つは、フックとは別です。** そして**順番が決まっています。番号のとおりです。**

> **⑯（鍵の移動）→ ⑰（バックアップを作る）→ ⑱（戻せることの確認）**

- **⑯を先にやる理由**：鍵がAIオフィスの中にあるままバックアップを作ると、
  **鍵も一緒にバックアップの保存先へ複製されます。** 過去の世代を残す方式
  （第9号の方式）では、**鍵が過去のバックアップに残り、すぐには削除できません**
- **⑰を⑱より先にやる理由**：バックアップがなければ、戻せるかを確かめられません

### ⑯　接続の鍵を、鍵を保管する専用フォルダへ移動する（**いちばん先**）

**鍵とは、外部のサービスにつなぐためのIDやパスワード、API キー、接続用の文字列**のことです。

1. **いま、AIオフィスの中に鍵があるかを探してください。**
   **`.claude/settings.json` の `Read(...)` の行に書かれている形**を、まず全部探します
   （`.env`・`.env.local` のような `.env.` で始まるもの・`*.env`・`*.key`・`*.pem`・
   `*.p12`・`*.pfx`・名前に `credential` を含むもの・
   名前に `token` または `secret` を含む JSON ファイル）。
   **それ以外にも、鍵が入っていそうなファイルがあれば挙げてください**
   （設定ファイル、メモ、社長が保存した接続情報など）。
   **禁止に書いていない形の鍵は、あなたに読めてしまいます。** だから探す側は広く見ます
2. **1つもなければ、それで済です。** メモ欄に「いま鍵は1つもない」と書いてください
3. **見つかったら、下の文で、専用フォルダの作成とファイルの移動について、社長の承認を取ってください。**
   - **ファイルは、フルパスで1行に1つずつ示してください。**
     「〈N〉個ありました」だけでは、社長はどのファイルのことか分かりません
   - **あなたは中身を読めません**（`.claude/settings.json` が禁止しています）。**それが正しい状態です。**
     **移動は、中身を読まずにできます。** `Read` を使わず、移動のコマンド
     （Windows＝PowerShell の `Move-Item`、Mac＝`mv`）で行ってください
   - **専用フォルダの場所**：Windows＝`C:\AI_Office_Secrets`（`C:\AI_Office` と同じ、Cドライブの直下）／
     Mac＝ホームフォルダの中の `AI_Office_Secrets`（`AI_Office` フォルダと同じ場所）。
     Mac のときは、文中の場所と括弧の説明を差し替えてください
   - **デスクトップや「ドキュメント」フォルダの中に作らないでください。**
     OneDrive や iCloud に自動で同期される設定になっていることがあり、鍵がクラウドへ複製されます
   - **社長が「第9号の手順で、鍵用のフォルダをもう作ってある」とおっしゃったら、そちらを使ってください。**
     新しく作りません

```
このAIオフィスの中に、外部のサービスに接続するための鍵（パスワードや API キーなど）を
含む可能性があるファイルが、〈N〉個ありました。

　〈ファイルのフルパス（1行に1つ）〉

鍵は、他人に知られると、社長のアカウントを勝手に使われてしまうおそれがある重要な情報です。
そのため、私（Claude Code）には、鍵を含むファイルの中身を読ませない設定にしてあります。

このあと、AIオフィスのバックアップを作成します。
鍵を含むファイルがAIオフィスの中に残っていると、鍵も一緒にバックアップの保存先へ複製され、
過去のバックアップに残って、すぐには削除できなくなります。

そこで、次のようにしてよろしいですか。

（1）鍵を保管するための専用フォルダを、私が作成する
　　 作成する場所：〈C:\AI_Office_Secrets〉（「AI_Office」フォルダと同じ、Cドライブの直下です）
（2）上のファイルを、私がそのフォルダへ移動する（ファイルの中身は読みません）

これから先も、パスワードや API キーなどの鍵を保存するときは、
このフォルダを保存先にすることをおすすめします。
よろしければ、「はい」とお答えください。
```

4. **「はい」と言われたら、フォルダを作成し、ファイルを移動してください。**
   移動したあと、**元の場所にファイルが残っていないこと**と、**移動先にファイルがあること**を、
   ファイル名の一覧だけで確かめます（中身は開きません）
5. メモ欄に「**鍵の保管先＝〈フォルダの場所〉／移動したファイル〈N〉個**」と書いて「済」にします。
   **これから鍵を読むプログラムを作るときは、このフォルダから読ませてください**
   （`.claude/skills/program-writing/` も同じ場所を指しています）

**⑯が終わってから、⑰へ進んでください。**

### ⑰⑱に入る前に：見送ってよいことを伝える（2026-09-16に追加）

**⑰⑱は、パソコンの操作に慣れた社長向けの作業です。** Google Cloud の画面での鍵の発行など、
非IT系の社長には難易度がとても高いことが、実機テストで分かりました（耕治さんの判断）。
**⑯が終わったら、⑰に入る前に、下の文で伝えて、社長に決めていただいてください。**

- **（2）なら**、⑰⑱を「**保留**」にし、理由に「**社長の判断で見送り（パソコンの操作に慣れてから行う）**」と書きます。
  `SETUP_STATUS.md` の「保留にしたものと、その理由」にも1行書きます。**保留は「未」ではないので、これで開設作業は終わりです**
- **見送ったあとに、⑰⑱を進めるよう、あなたから勧め直さないでください。** 社長が「続きをやりましょう」とおっしゃったときだけ、⑰から始めます
- **見送った社長に「バックアップがあります」と言わないでください。** `.claude/rules/safety.md`「その土台が、まだないことがあります」のとおりです

### ⑰　AIオフィスのバックアップを作る

**このキットには、バックアップの仕組みは入っていません。** 社長のアカウント・
保存先・パソコンの設定に結びついているので、ファイルとしては配れないからです。

**既定の方法は、ニュースレター第9号の方法（Google Drive へのバックアップ）です。**
ただし、社長がほかの保存先を希望されたら、そちらに合わせます。まず、次の文で聞いてください。

```
次に、AIオフィスのバックアップを作成します。
バックアップとは、AIオフィスのファイルの複製を、このパソコンとは別の場所にも保存しておく仕組みです。
パソコンが故障したときや、フォルダごと削除してしまったときに、ファイルを取り戻せます。

ニュースレター第9号では、Google Drive にバックアップする方法をご紹介しました。
次の3つのうち、どれに当てはまりますか。番号でお答えください。

（1）第9号の方法で、すでにバックアップを設定してある
　　→ 私が、バックアップが実行された記録を確認します。
（2）まだ設定していない。第9号と同じく、Google Drive にバックアップしたい
　　→ 第9号の方法で、私がご案内します。
（3）まだ設定していない。Google Drive 以外（OneDrive、外付けディスクなど）にバックアップしたい
　　→ ご希望の保存先を教えてください。その保存先に合わせた方法をご案内します。
```

**答えごとの進め方**

| 答え | あなたがすること |
|---|---|
| **（1）設定済み** | 自動実行の登録（Windows＝タスクスケジューラ、Mac＝launchd など）と、実行の記録（ログ）を確かめ、**最後に成功した日時**を見ます。**記録が見つからない、または直近に成功していないときは、「済」にしないでください。**見つかった事実をそのまま社長に伝え、（2）か（3）で作り直すかを聞きます |
| **（2）Google Drive** | **第9号の方法で進めます。** 社長にお願いするのは、Google Cloud の画面で接続用の鍵を発行するところだけです。**バックアップのプログラムの作成と、毎日の自動実行の設定は、あなたが行います**（`.claude/skills/program-writing/` と `.claude/skills/automation-setup/` を読んでから進めてください）。接続用の鍵は⑯の専用フォルダに置きます |
| **（3）ほかの保存先** | 希望の保存先を聞き、その保存先に合う方法を**案として示し、承認を取ってから**作ります。**第9号と同じ4つの条件を守ってください**＝①誤って削除・上書きしても以前の状態から戻せる方式にする（単純な同期にしない）②日付の分かる形で過去の分を残す ③鍵・一時ファイルを対象から外す ④成功・失敗の記録を残す |

**第9号の自動実行の設定は、Windows のタスクスケジューラを前提に書かれています。**
Mac のときは、同じ4つの条件を満たす方法を、案として示してから作ってください。

**画面の操作手順を、見ていないのに「確定」として伝えないでください。**
Google Cloud の画面などは変わります。**社長がいま見ている画面の写真を貼ってもらってから、次の1手だけを伝えてください。**
**画面の様子を文章で説明してもらわないでください。** 写真の撮り方と貼り方の案内の文は、`.claude/skills/connect-check/` の「画面の操作を案内するとき」にあります。
**鍵（クライアント シークレットなど）が表示される画面は、写真を撮らないよう、その手前で必ず伝えてください。** 鍵は、画面の「ダウンロード」のボタンで、ファイルとして保存してもらいます。
**作業にかかる時間の見込み（「15分ほど」など）は、伝えないでください。**

### ⑰を「済」にしてよい条件

**次の4つを、あなたが確かめてメモ欄に書けたら「済」です。社長に聞き直す必要はありません。**
設定したのはあなたか、設定の記録をあなたが確かめたので、答えはもう分かっています。

1. 保存先（例：Google Drive の「〇〇」フォルダ）
2. バックアップする範囲（例：AIオフィス全体。鍵を含むファイルと一時ファイルは除く）
3. 実行する時刻（例：毎日22時）
4. 残す期間（例：直近7日分と、直近4週分）

書けたら、次の文で社長に伝えます。

```
バックアップの設定が終わりました。次の内容を、進捗の表（SETUP_STATUS.md）に記録しました。

　保存先：〈例：Google Drive の「〇〇」フォルダ〉
　バックアップする範囲：AIオフィス全体（鍵を含むファイルと一時ファイルは除く）
　実行する時刻：〈例：毎日22時〉
　残す期間：〈例：直近7日分と、直近4週分〉
```

**1回も実行されていないうちは「済」にしないでください。** 手動で1回実行し、成功の記録が残ったことを確かめます。

**⑱（戻せることの確認）は、別のマスです。** ⑰の条件に混ぜないでください。
**⑰は「作った・実行された・場所が分かる」まで、⑱は「実際に戻せた」まで**です。

### ⑱　戻せることを確かめる（**いちばん最後**）

**⑰が「済」になってから行います。** ⑰が未のうちは、**⑱も未のまま**です。
（「バックアップがないので確かめられません」と、メモ欄に書いてください）

**保存されているだけでは保険になりません。** 次の文で承認を取ってから、あなたが確かめます。

```
最後に、バックアップから本当にファイルを元に戻せるかを確かめます。
保存されているだけでは、いざというときに戻せるかどうかが分からないためです。

私がテスト用ファイルを1つ作ってバックアップし、そのファイルを、
AIオフィスとは別のテスト用フォルダに戻して、中身が同じかを確認します。
AIオフィスの中のほかのファイルには、手を加えません。
進めてよろしいですか。
```

**確かめ方（第9号と同じです）**

1. AIオフィスの中にテスト用ファイルを1つ作り、バックアップを1回実行する
2. **テスト用ファイルをAIオフィスから削除し（社長が削除の禁止を希望していたら、削除は社長にお願いします）、もう一度バックアップを実行しても、
   保存先の過去の分にテスト用ファイルが残っていること**を確かめる
3. 保存先から、**AIオフィスとは別のテスト用フォルダ**へ、そのファイルを戻す
4. 戻したファイルと、最初に作ったファイルの中身が同じことを確かめる
5. テスト用フォルダとテスト用ファイルを片づけ、結果を社長に伝える

**本番のファイルや鍵に影響する可能性がある手順は、実行しないでください。**
理由と、影響のない代わりの方法を社長に伝えます。

**4まで実際に確かめてから「済」にしてください。** 「保存されているはず」で「済」にしないでください。

## すでに環境がある社長への対応（差分検証）

**別の手順を用意していません。上と同じ STEP 1 から始めてください。**

STEP 1 で数えると、多くのマスが最初から「済」になります。そのうえで、
STEP 2 で残りを見せるときに、**もう1つの一覧**を添えてください。

> **このキットにあって、お手元にないもの**

具体的には、`.claude/rules/` の3ファイルと、このキットのスキルに書かれている
ルールを、社長の環境の同じ場所と比較します。違いがあれば、
**1件ずつ「何が違うか」「入れると何が変わるか」**を書いて示します。

**勝手に入れないでください。** 1件ずつ社長の承認を取ります。
社長が「要らない」と言ったものは、それで終わりです。理由を聞き返さないでください。
