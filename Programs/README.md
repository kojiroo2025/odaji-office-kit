# プログラムの保存場所（`Programs` フォルダ）

**このフォルダは空です。** これから AI従業員が作るプログラムを、ここに入れます。

第9号「AI従業員が失敗しても、元に戻せる仕組みを作る」で、**`Programs` という名前で
作っていただいたフォルダ**です。すでにお持ちなら、そちらをお使いください。
保存場所を決めておかないと、作ったファイルがあちこちに散らばります。

---

## ここに入れるもの

AI従業員が作った、繰り返し使うプログラム。たとえば次のようなものです。

- 毎晩のバックアップを実行するプログラム（第9号）
- 決まった形の集計を出すプログラム
- 定期的に何かを確認するプログラム

**一度きりの作業のために書いた使い捨てのものは、ここに入れないでください。**
作業用のフォルダに置いて、終わったら消します。

繰り返し使うかどうかが分からないときは、社長に聞いてから決めてください。

## ここに入れてはいけないもの

**接続の鍵、認証情報、パスワードを、ここに置かないでください。**

**鍵を、AIオフィスのフォルダの外にある専用フォルダへ移動する作業は、進捗の表の⑯です。**
**まだ「未」のことがあります。**
**⑯が済んでいるかどうかにかかわらず、ここには置かないでください。**
プログラムが実行時にそこを読みに行くのは正常な動きです。**保存場所が
プログラムと同じになってはいけない**、ということです。

**理由は3つあります。1つ目は、どのパソコンでも当てはまります。**

1. **AI従業員の手の届くところに鍵があること自体が、危ないからです。**
   禁止事項は「この名前のファイルを読まない」という形で書かれているので、
   別の名前や別の呼び出し方で通る道が残ります。**そもそも置かないのが、いちばん確実です。**

**次の2つは、社長のパソコンによって、当てはまるかどうかが変わります。**
**当てはまるときは、害がさらに大きくなります。**

2. **変更履歴（`Git`）を使っている場合**：このフォルダは記録の対象です。
   **`Git` は一度記録すると、あとから消しても履歴に残ります。**
3. **AIオフィスのバックアップを設定している場合**：このフォルダも運ばれます。
   **鍵が外へ複製されます。**

## ログや一時ファイルについて

プログラムを動かすと、記録（ログ）や一時ファイルができることがあります。
これらは変更履歴に残す必要がありません。

AI従業員に、`.gitignore` へ足すかどうかを判断させ、**設定する前に社長へ
説明させてください。**

（**変更履歴（`Git`）をまだ入れていない場合、この作業は要りません。**
入れたときに、AI従業員が改めて判断します）

## AI従業員へ

このフォルダにプログラムを作ったら、次を守ってください。

- **場所を `CLAUDE.md` に書き加える**（次のセッションが探さなくて済むように）
- **鍵をこのフォルダに置かない**（上記のとおり）
- **作った直後に、実際に1回動かして結果を社長に見せる**
- 動かないときは、動かないと報告する。**動いたことにしない**

コードを書くときは、`.claude/rules/safety.md` の「渡してはいけないもの」を
先に読んでください。プログラムの中に、鍵やパスワードを直接書かないでください。

書き方と動かし方の決まりは、`.claude/skills/program-writing/` にあります。
プログラムを書く・直す・動かすときは、先に読んでください。
