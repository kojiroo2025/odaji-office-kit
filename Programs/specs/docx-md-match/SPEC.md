# 仕様：Word と元の原稿の照合（`docx-md-match`）

仕様のバージョン：1

この文書は、プログラムそのものではなく、**プログラムの仕様**です。
社長のパソコンの Claude Code が、この仕様を読んでプログラムを作り、
`tests/cases.json` のすべてのケースに合格してから使い始めます。
作る手順は、この文書の「作り方の手順」と、`Programs/specs/README.md` にあります。

---

## 目的

Claude Code が原稿（`.md`）から Word のファイル（`.docx`）を作ったとき、
**Word の本文が、確認した原稿と同じ文になっているか**を照合します。

社長が確認するのは原稿で、相手に渡すのは Word です。
Word にする途中で1行抜けたり、文が書き換わったりしても、見た目が整っていると、読み比べないかぎり気づきにくくなります。
このプログラムは、2つの本文を1文字ずつ比べ、違いがあれば最初に違う位置を表示します。

## 使う場面

- 議事録・報告書・提案書などを、原稿（`.md`）から Word にした直後。相手に渡す前
- 使えるのは、**自分たちが `.md` から作った `.docx`** だけです。外部から受け取った Word には使いません
- 見出し・箇条書き・太字だけの原稿に使います（表・リンク・斜体のある原稿は、不一致になります。「限界」）

## 呼び出し方

ここに書く引数の形・終了コード・標準出力の語は、`tests/cases.json` が前提にする**契約**です。
作る言語は問いませんが、この節と「終了コード」の節は変えないでください。

```
<プログラム> --md <原稿.md> --docx <作ったWord.docx> [--skip-title]
<プログラム> --selftest
```

| 引数 | 意味 |
|---|---|
| `--md <原稿.md>` | 元の原稿。UTF-8（先頭に BOM が付いていてもよい） |
| `--docx <作ったWord.docx>` | 原稿から作った Word |
| `--skip-title` | タイトルの行（原稿と Word の、それぞれ最初の空でない行）を比べない。Word でタイトルだけを書き直したときに使う。2つのタイトルを表示するので、目で確認する |
| `--selftest` | 自己試験。同じ文の組と違う文の組で、自分の判定を試す。すべて合格なら終了コード 0、不合格があれば 1 |

引数の決まりです。

- `--md` と `--docx` の両方がなければ、引数の誤り（終了コード 2）
- 知らない引数があるときは、何も照合せずに終了コード 2
- **`--selftest` と、ほかの引数（`--md`・`--docx`・`--skip-title`）を一緒に渡したら、終了コード 2 で止まる。**
  黙って無視すると、照合していないのに終了コード 0 が返ります
- 引数の途中までの書き方を、別の引数として受け付けない

標準出力の決まりです。

| 結果 | 標準出力に出す語 |
|---|---|
| 一致 | `一致` と、本文の字数。ヘッダー・フッターは照合していないことも添える |
| 不一致（文が違う） | `不一致` と、最初に違う位置（何字目か）、その前後の文字（原稿の側と Word の側） |
| 不一致（比べられない部品がある） | `不一致` と、見つけた部品の名前（下の表の「出す名前」）。どう直すかも添える |
| `--skip-title` を付けたとき | 上に加えて、原稿のタイトルと Word のタイトルの両方 |
| 読めなかった・照合できなかった | 標準出力に `一致` の語を出さない（`不一致` も出さない）。理由は標準エラーに出す |

**`一致` で始まる結果は、一致のときだけ出します。** 「不一致」には「一致」の2文字が含まれるので、
テストでは、一致のケースで「不一致」が出ていないことも確認します。

## 判定の規則

### Word の本文の取り出し方

`.docx` は zip の形のファイルです。

1. zip として開き、`word/document.xml` を読む。zip として開けない・この部品がない → 読めなかった（終了コード 2）
2. 根の要素の中の `body`（名前空間 `http://schemas.openxmlformats.org/wordprocessingml/2006/main`。以下、要素名はこの名前空間）がなければ、読めなかった
3. `body` の中のすべての段落（`p`。表の中の段落も含む）を、文書に出てくる順に並べる。
   1つの段落の文字は、その段落の中の `t` の文字を、順につなげたもの
4. **Word の側の文字は、行頭の記号も番号も、1文字も削りません**（Word では箇条書きは書式なので、文字として残っている記号は本文です）。
   例外は、下の「見出しだけの行」の末尾の「：」だけです
5. ヘッダー・フッター（`word/header*.xml`・`word/footer*.xml`）は読みません

XML の部品に共通の決まりです（`word/document.xml` と、下の脚注・コメントの部品）。

- 部品の先頭が UTF-16 の印（`FF FE`・`FE FF`）である、または先頭 200 バイトに 0 のバイトがある → 読めなかった
- 部品の中に `<!DOCTYPE` または `<!ENTITY`（大文字・小文字を区別しない）がある → 読まずに、読めなかった
- XML として読めない・展開できない・展開後の大きさが 200MB を超える → 読めなかった

### 原稿（`.md`）の読み方

1. UTF-8 として読む（先頭の BOM は外す。改行は CRLF でも LF でもよい）。
   **UTF-8 として読めなければ、読めなかった（終了コード 2）。** 化けたまま比べません
2. 1行ずつ、次の順に処理する
   1. 行頭の記号・番号を、**1回だけ**削る。削るのは、行頭の空白（半角スペース・タブ・全角スペース）に続く、次のどれか
      - `・`（後ろに空白がなくても削る。後ろの空白も削る）
      - `-` または `*` の1文字と、その後ろの1つ以上の空白
      - `#` が1〜6個と、その後ろの1つ以上の空白
      - 数字が1〜3けたと `.` と、その後ろの1つ以上の空白（`1. `・`10. `）
   2. 行の中の `**` を、すべて削る
3. 削らないもの（本文として扱う）
   - 後ろに空白のない `-`・`#`・番号（`-5%`・`#1`・`10.5日`）
   - 4けた以上の番号（`1234. `）
   - 行の途中の `・`（`東京・大阪`）
   - 削ったあとに残った、2つ目の記号（`- -5%` は、`-5%` が残る）

正規表現で書くと、行頭の記号・番号は次のとおりです（`　` は全角スペース）。

```
^[ \t　]*(?:・[ \t　]*|[-*][ \t　]+|#{1,6}[ \t　]+|\d{1,3}\.[ \t　]+)
```

### 見出しだけの行の「：」

行の前後の空白を除いたものが、「`：` でも `:` でもない文字が1〜20字」＋「`：` か `:` が1つ」＋「空白だけ」
の形なら、見出しだけの行として、末尾の「：」（と後ろの空白）を外します。

- **これは、原稿の行にも、Word の段落にも、同じように適用します**
  （原稿の「決まったこと：」と Word の「決まったこと」は一致。逆も一致）
- 「：」のあとに値がある行（`日時：2026/11/16`）は、見出しだけの行ではないので、「：」を残します

### 空白と改行の扱い

行（Word は段落）を改行でつないで1つの文字列にしてから、原稿と Word の両方に、同じ処理をします。

1. 英数字（ASCII の `A-Z` `a-z` `0-9`）と英数字のあいだにある空白・改行のまとまりは、**半角スペース1つにして残す**
   （`1 000` と `1000` は別の文。`Microsoft Teams` と `MicrosoftTeams` は別の文）
2. それ以外の空白・改行（全角スペースを含む）は、すべて削る

### `--skip-title`

原稿では「行頭の記号を削る前」の最初の空でない行、Word では最初の空でない段落を、それぞれ取り除いてから比べます。
取り除いた2つのタイトルは、標準出力に出します。

### 比べ方

処理したあとの2つの文字列が、完全に同じなら一致。違えば、先頭から数えて最初に違う位置を出します。

### 比べられない部品（文字が同じでも、不一致にする）

`body` の中に、次の要素が1つでもあれば、文字を比べた結果にかかわらず、**不一致（終了コード 1）** にします。
これらは、画面に見える文と、取り出した文字が食い違う原因になります。

| 要素名 | 出す名前 |
|---|---|
| `ins`・`del`・`delText`・`moveFrom`・`moveTo` | 変更履歴 |
| `vanish`・`webHidden` | 隠し文字 |
| `drawing`・`pict` | 図形（画像を含む） |
| `txbxContent` | テキストボックス |
| `oMath`・`oMathPara` | 数式 |
| `sym` | 記号の文字 |
| `object` | 埋め込み |
| `altChunk` | 外部の取り込み |
| `instrText`・`fldSimple` | フィールド（目次・ページ番号・計算式など） |
| `noBreakHyphen`・`softHyphen` | 特殊なハイフン（改行しないハイフン・行末でだけ表示されるハイフン） |

要素は、名前空間を除いた名前で見ます（別の名前空間の同じ名前の要素も、比べられない部品として扱います）。

あわせて、`word/footnotes.xml`（脚注）・`word/endnotes.xml`（文末脚注）・`word/comments.xml`（コメント）を、あれば読みます。
その中の `t` に、空白以外の文字が1つでもあれば、不一致（終了コード 1）にし、その部品の名前
（`footnotes.xml`・`endnotes.xml`・`comments.xml`）を出します。
部品があっても、文が入っていなければ（Word が自動で作る区切りだけなら）、そのまま比べます。

### 判定の順番

1. 原稿が読めない → 終了コード 2
2. Word が読めない（本文・脚注・文末脚注・コメントのどれかの部品が読めない）→ 終了コード 2
3. 原稿の、処理したあとの本文が0字 → 終了コード 2（照合できる文がない。**空どうしを「一致」にしない**）
4. 比べられない部品がある → 終了コード 1
5. 文字を比べる → 一致なら 0、違えば 1

### 偽の合格を出さないための決まり（まとめ）

- 読めないものを、一致にしない
- 原稿の本文が空のとき、一致にしない
- 比べられない部品があるとき、文字が同じでも一致にしない
- Word の側の文字を削って、一致に寄せない
- `--selftest` とほかの引数を同時に渡したら、止まる

## 終了コード

| 終了コード | 意味 |
|---|---|
| 0 | 一致 |
| 1 | 不一致。または、比べられない部品が Word にある。または、`--selftest` の不合格 |
| 2 | 読めなかった・引数の誤り・原稿の本文が空。**照合できていないので、合格ではありません** |

## やってはいけないこと

- 原稿にも Word にも書き込まない（読むだけ）
- 外部と通信しない
- 不一致のとき、Word や原稿を自動で直さない（違う位置を出すだけ）
- 自己試験で、自分が作った一時フォルダ以外のものを消さない

## 使う部品

**追加の部品（パッケージ）は要りません。** zip と XML を読む機能が標準で付いている言語なら、
標準の機能だけで作れます（Python なら `zipfile` と `xml.etree.ElementTree`）。
部品を足したくなったときは、`.claude/skills/program-writing/SKILL.md` の STEP 1 に従い、
1つずつ社長の了承を得てください。

## Windows と Mac の注意

- 画面への出力は UTF-8 にそろえます（Windows では、指定しないと日本語が化けることがあります）
- Windows のメモ帳などで保存した原稿は、先頭に BOM が付き、改行が CRLF のことがあります。どちらも読めるようにします
- シフト JIS で保存された原稿は、読めなかった（終了コード 2）にし、UTF-8 で保存し直すよう知らせます
- ファイルのパスに、日本語や空白が入っていても動くようにします

## 作り方の手順

1. `.claude/skills/program-writing/SKILL.md` を読み、その作法に従って書きます
2. 置き場所は `Programs/docx-md-match/` です（`Programs/README.md` の決まりに従い、場所を `CLAUDE.md` に書き足します）
3. `tests/cases.json` の全ケースを実行し、**すべて合格するまで直します**
   （実行の決まりは `Programs/specs/README.md`「テストの実行の決まり」）。
   合格しないケースを、ケースの側を書き換えて合格にしないでください
4. 自己試験（`--selftest`）にも、一致する組・一致しない組・読めないファイルを入れます
5. 書いた本人以外の目（経緯を知らない別の AI など）に、この仕様とプログラムをそのまま読ませ、
   「違う文なのに一致になる道」「読めないのに一致になる道」が残っていないかを見てもらいます。
   指摘を直したら、もう一度読ませます
6. 作ったプログラムの先頭に、「仕様のバージョン：1」と書いておきます

## 限界

- **次の組は「一致」になります。** 原稿の行頭の「10.」「-」が、番号・記号なのか本文なのかは、文字からは区別できないためです。
  行頭が数字や記号で始まる文は、一致と出ても目で確認してください
  - 原稿の「10. 5日」と Word の「5日」
  - 原稿の「- 3%」と Word の「3%」（マイナスの意味でも削ります）
- **表のある原稿は、不一致になります。** 原稿の表の記号（`|`）を取り除く処理がないためです。
  リンク（`[文字](URL)`）・斜体（`*文字*`）・コードの記号も同じです
- **スタイルの側で隠した文字と、白い文字などの読めない色の文字は、検出しません。**
  本文の文字として比べるだけです。原稿にない文があれば不一致になりますが、
  原稿にある文が Word で見えなくなっていても、一致になります
- ヘッダーとフッターは比べません。会社名や日付は、目で確認してください
- 比べるのは文字だけです。文字の大きさ・色・余白などの体裁は見ません
- 自動で付く番号（Word の箇条書きの番号）は書式なので、比べません
- テストの材料の `.docx` は、照合に必要な部品だけを入れた作り物です。Word で開くためのファイルではありません
