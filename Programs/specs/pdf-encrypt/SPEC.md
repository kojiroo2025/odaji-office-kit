# 仕様：PDF にパスワードを付ける（`pdf-encrypt`）

仕様のバージョン：1

この文書は、プログラムそのものではなく、**プログラムの仕様**です。
社長のパソコンの Claude Code が、この仕様を読んでプログラムを作り、
`tests/cases.json` のすべてのケースに合格してから使い始めます。
作る手順は、この文書の「作り方の手順」と、`Programs/specs/README.md` にあります。

**この仕様のプログラムは、外部の部品（パッケージ）が要ります。入れる前に、社長の承認を得てください**（「使う部品」）。

---

## 目的

PDF に、開くためのパスワードを付けた写しを作ります。暗号の方式は AES-256 です。

- 元の PDF は書き換えません。パスワードを付けた PDF を、別の名前で新しく作ります
- パスワードはプログラムが作り、**画面にも Claude Code との会話にも出しません。** 保存先のファイルにだけ書きます
- 作ったあと、正しく暗号化できたかをプログラム自身が確認し、確認に失敗したら何も残しません

## 使う場面

- 見積書・契約書・個人情報の入った PDF を、メールで社外へ送る前

作ったあとに、社長が行うことです（プログラムの完了の表示にも、同じ趣旨を出します）。

1. 保存先のファイルを**ご自身で**開き、パスワードを確認する
   （Claude Code に「パスワードを読んで」と頼まないでください。会話の記録に残ります）
2. PDF を送ったメールとは**別のメール**など、別の手段で相手にパスワードを伝える
3. 伝えたら、保存先のファイルを削除する

## 呼び出し方

ここに書く引数の形・終了コード・標準出力の語は、`tests/cases.json` が前提にする**契約**です。
作る言語は問いませんが、この節と「終了コード」の節は変えないでください。

```
<プログラム> <元.pdf> --out <出力.pdf> [--password-file <パスワードの保存先.txt>]
<プログラム> --selftest
```

| 引数 | 意味 |
|---|---|
| `<元.pdf>` | 元の PDF。書き換えない |
| `--out <出力.pdf>` | パスワードを付けた PDF の出力先。必ず指定する。すでにあれば止まる |
| `--password-file <保存先.txt>` | パスワードの保存先。省くと、パソコンの一時フォルダの中の `pdf_encrypt_passwords` フォルダに、毎回違う名前で作り、その場所を表示する |
| `--selftest` | 自己試験。一時フォルダに作り物の PDF を作って、動きを試す。終わったら、その一時フォルダを消す。すべて合格なら終了コード 0、不合格があれば 1、外部の部品が入っていなければ 2 |

引数の決まりです。

- 引数がない・`--out` がない → 引数の誤り（終了コード 2）
- **知らない引数（打ち間違えた `--dryrun` など）があるときは、何も作らずに終了コード 2**
- `--selftest` と、ほかの引数を一緒に渡したら、終了コード 2 で止まる
- 引数の途中までの書き方を、別の引数として受け付けない

標準出力の決まりです（成功したときだけ、標準出力に結果を出します）。

| 場面 | 出す語 |
|---|---|
| 成功（終了コード 0） | `パスワードを付けました`・`AES-256`・ページ数（`2ページ` の形）・出力の PDF のパス・パスワードの保存先のパス・「パスワードは PDF とは別の手段で伝え、伝えたら保存先のファイルを削除する」という案内 |
| 確認に失敗（終了コード 1） | 標準出力に `パスワードを付けました` を出さない。理由と、出力を残さなかったことを、標準エラーに出す |
| 何もしていない（終了コード 2） | 標準出力に `パスワードを付けました` を出さない。「何もしていない」ことと理由を、標準エラーに出す |

**パスワードそのものは、標準出力にも標準エラーにも、エラーの文にも出しません。**

パスワードの保存先のファイルの形です（UTF-8）。**2行目がパスワード**です（テストが、この行の文字が画面に出ていないことを確認します）。

```
PDF を開くパスワード
<パスワード>

対象の PDF：<出力の PDF のファイル名>
パスワードは、PDF とは別の手段（別のメールなど）で相手に伝え、伝えたらこのファイルを削除してください。
```

## 判定の規則

### 始める前の確認（1つでも当てはまれば、何も作らずに終了コード 2）

上から順に確認します。**この確認が終わるまで、ファイルもフォルダも作りません。**

1. 外部の部品が入っていない（入れ方を1行で知らせる）
2. 元・出力のどちらかの名前が `.pdf` で終わらない（大文字・小文字を区別しない）
3. 元の PDF がない
4. 出力が、元の PDF と同じファイル（元の PDF は上書きしない）
5. 出力先のフォルダがない（フォルダを勝手に作らない）
6. パスワードの保存先が、元の PDF または出力の PDF と同じファイル
7. **パスワードの保存先のフォルダが、出力の PDF のフォルダと同じ、またはその下の階層にある**
   （PDF と一緒に送ってしまわないため。フォルダごと圧縮して送ることもあるので、下の階層も不可）
8. 出力の PDF・書きかけのファイル（出力の名前に `.part` を足した名前）・パスワードの保存先の、どれかがすでにある（上書きしない）
9. 元の PDF を読めない（PDF ではない・壊れている）
10. 元の PDF に、すでにパスワードが付いている

ファイルが同じか・フォルダの上下は、絶対パスに直し、リンクを解き、Windows では大文字・小文字の違いをそろえてから比べます。
ドライブが違うときは、上下の関係はないものとして扱います。

### パスワードの作り方

- 16字。使う文字は、英字の大文字・小文字と数字から、見間違えやすい `0`・`O`・`1`・`l`・`I` を除いたもの
  （`ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnpqrstuvwxyz23456789`）
- **暗号に使える乱数**で作る（Python なら `secrets`。ふつうの `random` は使わない）
- 毎回違うパスワードを作る。利用者に決めさせない・引数で受け取らない（引数は、画面や記録に残るため）
- PDF の「権限のパスワード（所有者のパスワード）」は、開くパスワードとは別の乱数にし、どこにも保存しない

### 作る順番（途中で失敗しても、中途半端なものを残さない）

1. 元の PDF を読み、ページ数を数える（**パスワードのファイルを作る前に読む。** 読めない PDF のために、パスワードのファイルだけが残らないように）
2. パスワードの保存先のフォルダがなければ作り、パスワードのファイルを **「なければ作る」** の形で作る
   （すでにあれば失敗する開き方。あるかを調べてから作る、の2段にしない）。
   **PDF より先にパスワードを書く**（パスワードを書けないまま、だれも開けない PDF だけが残らないように）。
   書けなければ、終了コード 2
3. 暗号化した PDF を、書きかけの名前（出力の名前に `.part` を足した名前）で、「なければ作る」の形で書き出す。書き出せなければ、終了コード 2
4. 書きかけのファイルを開き直して、下の「作ったあとの確認」をする。失敗したら、終了コード 1
5. 確認に合格してから、書きかけのファイルを出力の名前にする。
   **このとき、出力の名前のファイルがすでにあれば、上書きせずに終了コード 2**
   （確認のあいだに、ほかの人や別のプログラムが同じ名前で作ったかもしれない。
   「あれば置き換える」動きの名前の変更は使わない。Windows の名前の変更は、移す先があれば失敗する。
   Mac・Linux では、ハードリンクを作ってから元を消すか、「なければ作る」で開いて写す）
6. **2〜5 のどこで失敗しても、この実行で新しく作ったファイル（パスワードのファイル・書きかけのファイル）を消してから終わる。**
   消すのは、この実行で作ったものだけ。前からあるファイルは消さない・書き換えない

### 作ったあとの確認（1つでも外れたら、確認の失敗＝終了コード 1。出力もパスワードのファイルも残さない）

1. PDF が暗号化されている
2. 暗号の方式が AES-256 である（PDF の暗号の辞書で、`/V` が 5、`/R` が 6、`/CF` の `/StdCF` の `/CFM` が `/AESV3`）
3. 空のパスワードでは開けない
4. 保存したパスワードで開ける
5. ページ数が、元の PDF と同じ
6. 確認の途中で想定していないエラーが起きたときも、確認の失敗として扱う

### 部品のバージョンの知らせ

読み込んだ部品のバージョンが、「使う部品」で決めたバージョンと違うときは、標準エラーに1行で知らせます。止めはしません。

### 偽の合格を出さないための決まり（まとめ）

- 確認していないものを、成功として表示しない（`パスワードを付けました` は、確認に合格したあとにだけ出す）
- 何もしていないとき（終了コード 2）と、作ったが確認に失敗したとき（終了コード 1）を、分けて知らせる
- 知らない引数で、ファイルを作らない
- `--selftest` とほかの引数を同時に渡したら、止まる

## 終了コード

| 終了コード | 意味 |
|---|---|
| 0 | 作成して、確認まで合格 |
| 1 | 作ったが確認に失敗した（暗号化できていない・ページ数が元と違う など）。出力は残していない。または、`--selftest` の不合格 |
| 2 | **何もしていない。** 引数の誤り・知らない引数・元の PDF が読めない・出力がすでにある・パスワードの保存先に書けない・外部の部品が入っていない、のどれか |

## やってはいけないこと

- **元の PDF を上書きしない・書き換えない**
- **パスワードを、画面・標準エラー・エラーの文・記録に出さない。** 引数や環境変数で受け取らない
- すでにあるファイルを上書きしない（出力・パスワードの保存先・書きかけのファイルのどれも）
- パスワードの保存先を、出力の PDF と同じフォルダ・その下のフォルダにしない
- 確認に失敗した出力を残さない。パスワードのファイルだけ・PDF だけ、という片方だけの状態を残さない
- この実行で作っていないファイルを消さない
- 外部と通信しない
- 暗号の処理を自分で書かない（広く使われている部品を使う）

## 使う部品

**標準の機能だけでは作れません。PDF の読み書きと、AES-256 の暗号の部品が要ります。**

Python で作るときは、次の2つを使います。

| 部品 | バージョン | 役割 |
|---|---|---|
| `pypdf` | 6.21.4 | PDF の読み書き |
| `cryptography` | 50.0.2 | AES-256 の暗号（`pypdf` が使う） |

```
pip install pypdf==6.21.4 cryptography==50.0.2
```

- **入れる前に、社長の承認を得ます。** `.claude/skills/program-writing/SKILL.md` の STEP 1 に従い、
  公式のページ（`https://pypi.org/project/pypdf/`・`https://pypi.org/project/cryptography/`）で、
  名前・利用者の多さ・最近の更新・保守している人を確認し、1つずつ社長に示して了承を得てから入れます
- 上のバージョンは、この仕様を書いた時点で、キットの作り手が決めたものです。入れる時点で、公式のページで
  このバージョンがあることを確認してください。より新しいバージョンに安全上の修正が出ていれば、
  社長に示したうえで新しいほうを使い、プログラムの中の「決めたバージョン」も合わせます
- 入れたら、部品の名前とバージョンを `Programs/README.md` に書き足します
- `pip install` は、この2つが使う部品（`cffi` など）も一緒に入れます。その部品のバージョンは固定していません
- ほかの言語で作るときも、PDF の AES-256（`/V` 5・`/R` 6）に対応した、広く使われている部品を選び、同じ手順で承認を得ます

## Windows と Mac の注意

- 画面への出力は UTF-8 にそろえます（Windows では、指定しないと日本語が化けることがあります）
- ファイルのパスに、日本語や空白が入っていても動くようにします（テストに、日本語と空白の入った出力の名前のケースがあります）
- **書きかけのファイルを出力の名前にする方法は、Windows と Mac で変えます**（「作る順番」の5）。
  Mac・Linux の名前の変更は、移す先のファイルを黙って上書きします
- PDF とパスワードのファイルは、バイトのまま書きます（改行の変換をしない開き方にする）
- パスワードのファイルは、作るときに、持ち主だけが読める権限（`0600`）を指定します（Windows では、この指定は効きません）
- 一時フォルダの場所は、Windows と Mac で違います。プログラムの言語の機能で調べ、直接書かないでください

## 作り方の手順

1. `.claude/skills/program-writing/SKILL.md` を読み、その作法に従って書きます
2. 「使う部品」の手順で、社長の承認を得てから部品を入れます
3. 置き場所は `Programs/pdf-encrypt/` です（`Programs/README.md` の決まりに従い、場所を `CLAUDE.md` に書き足します）
4. `tests/cases.json` の全ケースを実行し、**すべて合格するまで直します**
   （実行の決まりは `Programs/specs/README.md`「テストの実行の決まり」）。
   合格しないケースを、ケースの側を書き換えて合格にしないでください
5. **テストの材料では確認できない部分を、自己試験（`--selftest`）で確認します。** 外から失敗を起こせないので、自己試験の中で、部品を作り物に差し替えて試します
   - 出力が、保存したパスワードで開け、違うパスワード・空のパスワードでは開けないこと。AES-256 であること
   - 2回実行して、パスワードが毎回違うこと。パスワードが16字で、決めた文字だけでできていること
   - 元の PDF のバイトが、実行の前後で変わらないこと
   - 写すときにページが落ちた出力が、確認の失敗（終了コード 1）になり、出力もパスワードのファイルも残らないこと
   - パスワードのファイルを途中で書けなくなったとき（空きがない など）に、終了コード 2 で止まり、何も残らないこと
   - 確認のあいだに、出力と同じ名前のファイルができたときに、それを上書きせず、終了コード 2 で止まること
   - 書きかけのファイルを出力の名前にする部品が、どの方法でも、すでにあるファイルを上書きしないこと
   - `--password-file` を省いたときに、一時フォルダに保存し、場所だけを表示すること
6. 書いた本人以外の目（経緯を知らない別の AI など）に、この仕様とプログラムをそのまま読ませ、
   「パスワードが画面や記録に出る道」「すでにあるファイルを上書きする道」「確認していないのに成功と表示する道」
   「失敗したときに片方だけが残る道」が残っていないかを見てもらいます。指摘を直したら、もう一度読ませます
7. 最初に使うときは、作った PDF を、社長が PDF のソフトで開いて確認します（パスワードを聞かれること・開けること）
8. 作ったプログラムの先頭に、「仕様のバージョン：1」と書いておきます

## 限界

- **パスワードを PDF と同じメールで送ると、付けた意味がなくなります。** 伝え方は、このプログラムでは守れません
- 付けるのは「開くためのパスワード」です。開いたあとの印刷・コピーの制限は付けません
- すでにパスワードが付いている PDF は扱いません（終了コード 2）
- **壊れた PDF は直しません。** 元の PDF が壊れていて読めないときは終了コード 2、
  読めてもページ数が出力と合わないときは終了コード 1 で止まり、出力を残しません。
  確認するのはページ数までです。各ページの中身（文字・画像）が元と同じかは比べません
- 電子署名のある PDF には使わないでください（写しを作ったときに署名が保たれるかを、このプログラムは確認しません）
- 10年以上前の古い PDF のソフトでは、AES-256 の PDF を開けないことがあります
- パスワードの保存先を一時フォルダ以外にしたときは、そこがバックアップや変更履歴（`Git`）の対象でないことを確認してください
- `--password-file` を省いたときの動き（一時フォルダへの保存）は、`tests/cases.json` に入れていません
  （テストのたびに、パソコンの一時フォルダにファイルが残るため）。自己試験で確認します
- テストの材料の PDF は、白紙のページだけの作り物です。`encrypted.pdf` のパスワードは、作ったときに捨てています（だれも開けません）
