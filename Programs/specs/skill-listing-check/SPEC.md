# 仕様：スキルの説明が届いているかの検査（`skill-listing-check`）

仕様のバージョン：1

この文書は、プログラムそのものではなく、**プログラムの仕様**です。
社長のパソコンの Claude Code が、この仕様を読んでプログラムを作り、
`tests/cases.json` のすべてのケースに合格してから使い始めます。
作る手順は、この文書の「作り方の手順」と、`Programs/specs/README.md` にあります。

---

## 目的

AIオフィスのスキル（`.claude/skills/` の下の手順書）が、**Claude Code に説明付きで届いているか**を検査します。

Claude Code は、セッションを始めるときにスキルの一覧（名前と説明）を受け取り、
その説明（description）を読んで、どのスキルを使うかを選びます。
この一覧には文字数の上限があり、スキルが増えて上限を超えると、
**使用頻度の低いスキルから、説明が消えて名前だけになります。**
説明が消えたスキルは選ばれにくくなり、さらに使われなくなります。エラーにはならず、画面にも知らせは出ません
（警告は、`--debug` を付けて起動したときの記録にだけ書かれます）。

このプログラムは、パソコンに残っているセッションの記録から、実際に届いた一覧を読み、
説明が消えたスキル・一覧に載っていないスキルを数えます。

## 使う場面

- スキルを足したあと・スキルの説明（description）を長くしたあと
- 「前は使われていたスキルが、最近使われない」と感じたとき
- 月に1回の見直しのとき

## 呼び出し方

ここに書く引数の形・終了コード・標準出力の語は、`tests/cases.json` が前提にする**契約**です。
作る言語は問いませんが、この節と「終了コード」の節は変えないでください。

```
<プログラム> [--office <AIオフィスのフォルダ>] [--max-age-hours <時間>]
<プログラム> --selftest
```

| 引数 | 意味 |
|---|---|
| `--office <フォルダ>` | AIオフィスのフォルダ。省くと、いまのフォルダ。フォルダがなければ終了コード 2 |
| `--max-age-hours <時間>` | これより古い一覧では判定しない。省くと 48。1以上の整数。0以下なら、引数の誤り（終了コード 2） |
| `--selftest` | 自己試験。作り物のスキルとセッションの記録を一時フォルダに置き、自分の判定を試す。終わったら、その一時フォルダを消す。すべて合格なら終了コード 0、不合格があれば 1 |

テストのための引数です（ふだんは使いません。`tests/cases.json` が、作り物のフォルダで実行するために使います）。

| 引数 | 意味 |
|---|---|
| `--skills-dir <フォルダ>` | スキルのフォルダ。渡すと、既定の2か所を読まず、渡したフォルダだけを読む。繰り返して、複数を渡せる |
| `--records-dir <フォルダ>` | セッションの記録のフォルダ。渡すと、ホームフォルダの `.claude/projects/` を探さず、このフォルダの直下の `.jsonl` を、AIオフィスの記録として読む。フォルダがなければ終了コード 2 |
| `--now <時刻>` | いまの時刻の代わりに使う時刻（ISO 8601。例 `2026-10-31T12:00:00Z`）。時刻として読めなければ、引数の誤り（終了コード 2） |

引数の決まりです。

- 知らない引数があるときは、何も検査せずに終了コード 2
- **`--selftest` と、ほかの引数（テストのための引数を含む）を一緒に渡したら、終了コード 2 で止まる。**
  黙って無視すると、検査していないのに終了コード 0 が返ります
- 引数の途中までの書き方を、別の引数として受け付けない

標準出力の決まりです。

| 場面 | 標準出力に出す語 |
|---|---|
| 判定できたとき | `一覧の時刻=<時刻>`・`一覧の文字数=<数>`・`手元のスキル=N本`・`問題のあるスキル=N本` |
| 記録を読んだあとは、いつも | `読んだ記録=N本`・`読めなかった記録=N本`・`読めなかったスキル=N本` |
| 判定できたとき | `一覧に出ない設定のスキル=N本`（本数だけ。**名前は出さない**） |
| 問題のあるスキルごとに1行 | スキルの名前と、`description がない` または `一覧に名前がない` |
| 判定できないとき | 理由と、次にすること（新しいセッションを始めてから、もう一度実行する など） |

- `手元のスキル` は、一覧に出るはずのスキルの本数です（一覧に出ない設定のスキルは含めません）
- **`問題のあるスキル=0本` は、判定できて、問題がなかったときにだけ出します。**
  判定できないとき（終了コード 2）に、この語を出さないでください
- **セッションの記録の本文は、画面に出しません。** 出すのは、一覧の時刻・文字数・スキルの名前・本数だけです

## 判定の規則

### 手元のスキルの読み方

1. 読むフォルダは、`<AIオフィス>/.claude/skills/` と、`<ホームフォルダ>/.claude/skills/` の2か所
   （`--skills-dir` を渡したときは、渡したフォルダだけ）。フォルダがなければ、スキル0本として扱う。
   **ただし、パスはあるのにフォルダとして開けない（行き先の消えたリンク・ファイル など）ときは、「読めなかったスキル」として1本数える**
   （Python の `Path.is_dir()`・`glob()` は、行き先の消えたリンクで、エラーを出さずに False・空の一覧を返します）
2. それぞれのフォルダの、直下のフォルダにある `SKILL.md` を読む（UTF-8。先頭の BOM は外す）
3. スキルの名前は、フロントマター（1行目が `---` で、次の `---` までの部分。400行まで）の `name:` の値。
   値を囲む引用符は外す。`name:` がない・フロントマターがないときは、フォルダの名前
4. フロントマターの中に `disable-model-invocation: true` の行があるスキルは、**一覧に出ない設定のスキル**
   （社長が `/名前` で呼ぶ専用のスキル。一覧に載らないのが正しい動き）。
   `true` は大文字・小文字を区別せず、引用符で囲んであってもよい。行の後ろの `#` のコメントは無視する
   - `disable-model-invocation: false` は、一覧に出るはずのスキル
   - **フロントマターの外（本文）に書いてある `disable-model-invocation: true` は、設定として読まない**
5. 同じ名前が、一覧に出るはずのスキルと、出ない設定のスキルの両方にあるときは、一覧に出るはずのスキルとして数える
6. **スキルのフォルダそのものを読めない・`SKILL.md` を開けないときは、黙って飛ばさず、「読めなかったスキル」として本数を数える**

### セッションの記録の探し方

Claude Code は、セッションの記録を `<ホームフォルダ>/.claude/projects/<名前>/` の下の `.jsonl` に保存します。
`<名前>` は、セッションを始めたフォルダの絶対パスの、英数字以外の文字を、すべて `-` に置き換えたものです。

1. `<ホームフォルダ>/.claude/projects/` がなければ、判定できない（終了コード 2）
2. AIオフィスのフォルダの絶対パスから `<名前>` を作り、そのフォルダがあれば、その直下の `.jsonl` を候補にする
   （「名前で特定できた」）
3. そのフォルダがなければ、`projects/` の直下のすべてのフォルダの `.jsonl` を候補にし、
   記録の中の `cwd` で見分ける（「名前で特定できなかった」）
4. 子の記録（`subagents` などの、さらに下のフォルダ）は見ない
5. 候補を、ファイルの更新日時の新しい順に並べ、新しいものから 40 本を読む
6. `--records-dir` を渡したときは、1〜3 の代わりに、渡したフォルダの直下の `.jsonl` を候補にし、「名前で特定できた」ものとして扱う

### 一覧の読み方

記録は、1行が1つの JSON です。次の行だけを使います。

1. 行に `"skill_listing"` の文字がない行は、読み飛ばす（JSON として読めない行でも、問題にしない）
2. `"skill_listing"` の文字があるのに、JSON として読めない行があったら、**その記録を「読めなかった記録」として数える**
   （いちばん新しい一覧が、その行かもしれないため）
3. JSON の `attachment` が項目の集まりで、その `type` が `skill_listing` のものだけを、一覧として扱う
   （会話の文の中に `skill_listing` と書いてあるだけの行は、一覧ではない）
4. 一覧の `cwd` が文字列のとき：AIオフィスのフォルダと同じ場所でなければ、使わない
   （どちらも絶対パスに直し、リンクを解き、Windows では大文字・小文字と `\` `/` の違いをそろえてから比べる）
5. 一覧に `cwd` がないとき：「名前で特定できた」ときだけ使う。「名前で特定できなかった」ときは使わない
6. 一覧の本文は `attachment.content`、時刻は `timestamp`。**本文が文字列ではない・時刻が空か時刻として読めない一覧があったら、
   その記録を「読めなかった記録」として数える**（黙って捨てると、もっと古い一覧で合格になります。
   記録の形が変わった直後に起きやすい）。時刻に時間帯の指定がなければ、UTC として読む
7. 一覧の本文から、手元の一覧に出るはずのスキルの名前ごとに、
   「`- <名前>`」だけの行、または「`- <名前>:<説明>`」の行を探す（行の全体がこの形。同じ名前の行が複数あれば、最初の行）。
   - 行があり、`:` のあとに空白以外の文字があれば、説明が届いている
   - 行があるが、`:` がない・`:` のあとが空なら、**description がない**
   - 行がなければ、**一覧に名前がない**
   - 手元にない名前の行・説明の中の箇条書きは、数えない
8. **見つかった名前の行の数が、手元の一覧に出るはずのスキルの本数の 8 割未満の一覧は、全体の一覧として読まない**
   （Claude Code は、変更のあったスキルだけを再送することがあります。部分の再送を「全体」と読むと、載っていないスキルをすべて問題に数えてしまいます）
9. 読んだすべての記録の、全体の一覧のうち、**時刻（`timestamp` の文字列）がいちばん新しいもの**を採る。
   ファイルの更新日時が新しくても、長く開いたセッションの一覧は古いので、読む本数の全部を読んでから決める
10. 開けない記録（権限がない・ファイルではない など）は、黙って飛ばさず、「読めなかった記録」として本数を数える

### 判定の順番

1. 記録の場所がない → 判定できない（終了コード 2）
2. 一覧に出るはずのスキルが0本 → 判定できない（終了コード 2）
3. 全体の一覧が1つも見つからない → 判定できない（終了コード 2）
4. 採った一覧の時刻が、いまの時刻より1時間を超えて未来 → 判定できない（終了コード 2。パソコンの時計の狂い）。
   採った一覧の時刻が、いまの時刻より `--max-age-hours`（既定 48）時間を超えて古い → 判定できない（終了コード 2）
5. 問題のあるスキル（description がない・一覧に名前がない）を、名前の順に出す
6. **読めなかった記録・読めなかったスキルが1本でもあれば、判定できない（終了コード 2）。**
   読めた分で見つかった問題のスキルは表示してよいが、合格にも不合格にもしない。
   このときは `問題のあるスキル=N本` の語を出さない（`問題のあるスキル=0本` と出すと、出力だけを読んだ人が合格と読むため。
   例：`読めた分で見つかった問題のスキル=0本（確定ではありません）`）
7. 問題のあるスキルが1本でもあれば終了コード 1、なければ 0

### 偽の合格を出さないための決まり（まとめ）

- 古い一覧・未来の時刻の一覧で、合格にしない
- 形の崩れた一覧を黙って捨てて、もっと古い一覧で合格にしない
- 部分の再送を、全体の一覧として読まない
- ほかのフォルダのセッションの一覧で、判定しない
- 読めなかった記録・スキルを、黙って飛ばさない（本数を出し、合格にしない）
- スキルが0本のとき、「問題なし」にしない
- 自分の判定の部分が壊れているとき（自己試験の、判定の部分に不合格があるとき）は、検査の結果を出さずに終了コード 2 にする
- `--selftest` とほかの引数を同時に渡したら、止まる

## 終了コード

| 終了コード | 意味 |
|---|---|
| 0 | すべてのスキルに説明が届いている |
| 1 | 説明がない、または一覧に名前がないスキルがある。または、`--selftest` の不合格 |
| 2 | 判定できない、または引数の誤り。**検査できていないので、合格ではありません** |

## やってはいけないこと

- どのファイルにも書き込まない（読むだけ）
- セッションの記録の本文を、画面・ファイル・外部に出さない
- 外部と通信しない
- 説明が消えていても、スキルを自動で書き換えない（見つけるだけ。直す案は、社長に見せてから）
- 自己試験で、自分が作った一時フォルダ以外のものを消さない

## 使う部品

**追加の部品（パッケージ）は要りません。** JSON とファイルを読む機能が標準で付いている言語なら、
標準の機能だけで作れます。
部品を足したくなったときは、`.claude/skills/program-writing/SKILL.md` の STEP 1 に従い、
1つずつ社長の了承を得てください。

## Windows と Mac の注意

- 画面への出力は UTF-8 にそろえます（Windows では、指定しないと日本語が化けることがあります）
- ホームフォルダの場所は、プログラムの言語の機能（Python なら `Path.home()`）で調べ、パスを直接書かないでください
- 記録のフォルダの `<名前>` は、Windows では `C:\AI_Office` が `C--AI-Office` になります（`:` と `\` と `_` が、それぞれ `-` になる）。
  Mac では `/Users/taro/AI_Office` が `-Users-taro-AI-Office` になります
- Windows では、フォルダの名前の大文字・小文字を区別しません。`cwd` を比べるときは、そろえてから比べます
- 開けない記録の作り物（`.jsonl` という名前のフォルダ）を開こうとしたときのエラーの種類は、Windows と Mac で違います。
  どちらのエラーでも、「読めなかった記録」として数えるようにします

## 作り方の手順

1. `.claude/skills/program-writing/SKILL.md` を読み、その作法に従って書きます
2. 置き場所は `Programs/skill-listing-check/` です（`Programs/README.md` の決まりに従い、場所を `CLAUDE.md` に書き足します）
3. `tests/cases.json` の全ケースを実行し、**すべて合格するまで直します**
   （実行の決まりは `Programs/specs/README.md`「テストの実行の決まり」）。
   合格しないケースを、ケースの側を書き換えて合格にしないでください
4. **テストの材料では確認できない部分を、自己試験（`--selftest`）と、実際の記録で確認します。**
   - 自己試験の一時フォルダで、「AIオフィスのパスから `<名前>` を作って記録のフォルダを特定する」
     「特定できないときに `cwd` で見分ける」「`cwd` が AIオフィスと同じ一覧を採る」の3つを試します
     （テストの材料は、置かれる場所によって絶対パスが変わるので、この3つを入れられません）
   - 全ケースに合格したあと、AIオフィスのフォルダで、テストのための引数を付けずに1回実行します。
     「判定できない：記録の場所がありません」「全体の一覧がありません」と出たら、
     記録の形が、この仕様を書いた時点から変わっているかもしれません。社長に知らせてください
5. 書いた本人以外の目（経緯を知らない別の AI など）に、この仕様とプログラムをそのまま読ませ、
   「古い一覧・部分の一覧で合格になる道」「読めなかったものを黙って飛ばす道」が残っていないかを見てもらいます。
   指摘を直したら、もう一度読ませます
6. 作ったプログラムの先頭に、「仕様のバージョン：1」と書いておきます

## 限界

- 見るのは、AIオフィスのフォルダの `.claude/skills/` と、ホームフォルダの `.claude/skills/` にあるスキルだけです。
  プラグインのスキルと、Claude Code に最初から入っているスキルは見ません
- 見るのは、パソコンに残っている過去のセッションの記録です。
  スキルを変えた直後は、新しいセッションを1つ始めてから実行してください
- AIオフィスのフォルダそのもので始めたセッションだけを見ます。下のフォルダで始めたセッションは見ません
- **セッションの記録の形（保存場所・`skill_listing` の行の形）は、Claude Code が公開している仕様ではありません。**
  この仕様を書いた時点の、実際の記録の形をもとにしています。Claude Code のバージョンが上がると、変わることがあります。
  変わったときは、終了コード 2（判定できない）になるように作ります。合格（0）にはしません
- 説明が届いていることと、そのスキルが正しい場面で選ばれることは別です。
  選ばれ方は、実際に頼んでみて確認してください
- テストの材料のスキル（`skills_base` など）は作り物です。`.claude/skills/` の下には置いていないので、Claude Code のスキルとしては読み込まれません
