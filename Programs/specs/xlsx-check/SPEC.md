# 仕様：Excel のファイルの検査（`xlsx-check`）

仕様のバージョン：1

この文書は、プログラムそのものではなく、**プログラムの仕様**です。
社長のパソコンの Claude Code が、この仕様を読んでプログラムを作り、
`tests/cases.json` のすべてのケースに合格してから使い始めます。
作る手順は、この文書の「作り方の手順」と、`Programs/specs/README.md` にあります。

---

## 目的

Claude Code がプログラムで作った、または書き換えた Excel のファイル（`.xlsx`）を、
相手に渡す前に検査します。

プログラムで作った `.xlsx` は、Excel で開いたときに、内容に問題があるとして修復するかを聞く画面が出ることがあります。
作った側はプログラムで書くだけで Excel で開かないので気づかず、**受け取った相手が開いて初めて表に出ます。**
このプログラムは、その画面の原因になりうる3つの型を、Excel を使わずに探します
（作り手の環境で修復を求められたファイルにあった2つの型〔C-1・C-2〕と、Excel の仕様の上限を超える行の高さ〔C-3〕）。

| 記号 | 見るもの | 起きる例 |
|---|---|---|
| C-1 | 列の幅の定義が、重なっていないか・順番どおりか・列の番号が 1〜16384 の範囲か | F〜G 列をまとめた定義があるファイルを読み、G 列だけの幅を変えて保存すると、「F〜G」と「G」の2つの定義が重なる |
| C-2 | 空白だけの文字の部品に、空白を保つ指定が付いているか | 1つのセルの中で文字の色を分けたとき、空白1文字だけの部品ができる |
| C-3 | 行の高さが、0 以上で Excel の上限（409 ポイント）以下の数か | 高さを計算で決めたとき、上限を超える・数でない値になる |

## 使う場面

- Claude Code に `.xlsx` を作らせた・書き換えさせた直後。お客様や取引先に渡す前
- 人が Excel で作って保存しただけのファイルは、この検査の対象にしていません（3つの型は、プログラムで書いたときにできる型です）

## 呼び出し方

ここに書く引数の形・終了コード・標準出力の語は、`tests/cases.json` が前提にする**契約**です。
作る言語は問いませんが、この節と「終了コード」の節は変えないでください。

```
<プログラム> <ファイル.xlsx> [<ファイル.xlsx> ...]
<プログラム> --selftest
```

| 引数 | 意味 |
|---|---|
| `<ファイル.xlsx>` | 検査するファイル。1つ以上。いくつ並べてもよい |
| `--selftest` | 自己試験。問題のないファイルと問題のあるファイルを一時フォルダに作り、自分の判定を試す。終わったら、その一時フォルダを消す。すべて合格なら終了コード 0、不合格があれば 1 |

引数の決まりです。

- 引数が1つもないときは、引数の誤り（終了コード 2）
- 知らない引数（`--nazo` など）があるときは、何も検査せずに終了コード 2
- **`--selftest` と検査するファイルを一緒に渡したら、終了コード 2 で止まる。**
  黙ってファイルを無視すると、検査していないのに終了コード 0 が返ります
- 引数の途中までの書き方（`--self` など）を、別の引数として受け付けない

標準出力の決まりです（ファイル1つごと）。

| 結果 | 1行目に出す語 | そのあとに出すもの |
|---|---|---|
| 問題なし | `問題なし` と、ファイルのパス | なし |
| 問題あり | `問題 N 件`（N は件数。`問題 2 件` の形）と、ファイルのパス | 問題ごとに、場所（シート名、または `sharedStrings.xml`）・記号（`C-1` `C-2` `C-3`）・下の表のもの |
| 読めなかった | `読めなかった` と、ファイルのパス | 理由（どの部品が、なぜ読めないか） |

| 記号 | 出すもの |
|---|---|
| C-1 | 列を英字で出す。範囲は `F〜G` の形、1列なら `G`。重なり・逆順のときは、その定義（後ろ側）と、前の定義の両方。min・max が数でない・範囲外のときは、`min=0` `max=16385` の形で元の値 |
| C-2 | セルの中の文字列ならセル番地（`B3`）。共有文字列なら、その番号と、使っているセル（`「シート名」C7` の形。10か所まで。どのセルも使っていないときは、その旨） |
| C-3 | 行番号を `5行目` の形で出し、元の値も出す |

**`問題なし` の語は、問題がなかったファイルにだけ出します。**
読めなかったファイル・問題のあるファイルの出力に、`問題なし` を出さないでください。

## 判定の規則

`.xlsx` は zip の形のファイルで、中に XML の部品が入っています。次の順に読みます。

### 読み方（ここで読めなければ「読めなかった」。合格にしない）

1. zip として開く。開けなければ、読めなかった
2. `xl/workbook.xml` と `xl/_rels/workbook.xml.rels` を読む。どちらかがなければ、読めなかった
3. `workbook.xml` の `sheet` の要素を、並び順に読む。それぞれの `r:id` を `workbook.xml.rels` の `Relationship` の `Id` と突き合わせ、`Target` からシートの部品のパスを決める
   （`Target` が `/` で始まれば、先頭の `/` を取ったもの。そうでなければ `xl/` を前に付け、`..` を解いたもの）
4. **`r:id` が `workbook.xml.rels` にないシートがあれば、読めなかった。**
   黙って飛ばすと、そのシートを1行も見ずに「問題なし」を返します
5. シートが1つもなければ、読めなかった
6. シートの部品が zip の中になければ、読めなかった
7. **シートの部品の根の要素が、`worksheet`・`chartsheet`・`dialogsheet` のどれかで、
   名前空間が `http://schemas.openxmlformats.org/spreadsheetml/2006/main` でなければ、読めなかった。**
   根が違うと、中の列の定義や行を1つも見つけられず、「問題なし」になってしまいます
   （名前空間がない・別の名前空間・別の要素名、のどれも読めなかった。
   「Strict Open XML スプレッドシート」の形式は名前空間が違うので、読めなかったになります）
8. `xl/sharedStrings.xml` は、あれば読む（なくてもよい）

すべての XML の部品に共通の決まりです。

- 部品の先頭が UTF-16 の印（`FF FE`・`FE FF`）である、または先頭 200 バイトに 0 のバイトがある → 読めなかった
- 部品の中に `<!DOCTYPE` または `<!ENTITY`（大文字・小文字を区別しない）がある → 読まずに、読めなかった
- XML として読めない → 読めなかった
- 展開後の大きさが 200MB を超える部品 → 読めなかった
- 展開の途中でエラーになる部品（壊れている・パスワード付き・知らない圧縮の方式）→ 読めなかった
- **想定していないエラーが起きたときも、「問題あり（1）」ではなく「読めなかった（2）」にする**

### C-1　列の幅の定義

シートの部品の `cols` の中の `col` を、書かれている順に見ます（`cols` がなければ、問題なし）。

- `min`・`max` が、どちらも ASCII の数字だけの文字列でなければ、問題（`-1`・空・`1.5` は数字だけではない）。この定義は、以降の比較に使わない
- `min`・`max` のどちらかが 1〜16384 の外なら、問題。この定義は、以降の比較に使わない
- `min` が `max` より大きければ、問題
- `min` が、それまでの定義の `max` のうち、いちばん大きいもの以下なら、問題（重なっている、または順番が逆）

### C-2　空白だけの文字の部品

「空白だけの文字の部品」とは、`t` の要素で、文字が1文字以上あり、
そのすべてが XML の空白（半角スペース・タブ・CR・LF の4つ）で、
`xml:space="preserve"` が付いていないものです。

- **全角スペースは、XML の空白ではないので、問題にしません**
- 文字が0文字の `t` は、問題にしません
- セルの中の文字列（`c` の中の `is` の中の `t`）：1つのセルにつき、問題は1件として出す
- 共有文字列（`sharedStrings.xml` の `si` の中の `t`）：`si` 1つにつき、問題は1件として出す。
  使っているセル（`t="s"` で、`v` がその番号のセル）を、シート名と番地で添える。
  **どのセルも使っていなくても、問題として出す**

### C-3　行の高さ

`sheetData` の中の `row` の `ht` を見ます（`ht` がなければ、見ない）。

- `ht` が、ふつうの数の形（符号・数字・小数点・指数だけ。ASCII の数字）でなければ、問題。
  **`nan`・`inf`・`1_0` を、数として受け付けないでください**
  （プログラムの言語によっては、これらを数として読みます。先に形を確認します）
- 数として読んだ結果が、限りのある数でなければ、問題（`1e999` は無限大になる）
- 0 より小さければ、問題
- 409 より大きければ、問題（0 と 409 は、問題なし。409.5 は問題）。上限の 409 ポイントは、Microsoft の
  サポートのページ「Excel の仕様と制限」にある「行の高さ 409 ポイント」です

### 偽の合格を出さないための決まり（まとめ）

- 読めないものを、合格にしない（終了コード 2 は、合格ではない）
- シートを1枚でも見られなかったら、合格にしない
- `--selftest` と検査対象を同時に渡したら、止まる
- 知らない引数で、検査したことにしない

## 終了コード

| 終了コード | 意味 |
|---|---|
| 0 | 問題なし |
| 1 | 問題あり。または、`--selftest` の不合格 |
| 2 | 読めなかった、または引数の誤り。**検査できていないので、合格ではありません** |

ファイルを複数渡したときは、ファイルごとの結果のうち、いちばん大きい番号で終わります
（合格と読めなかったが混ざれば 2）。1つが読めなくても、残りのファイルの検査は続けます。

## やってはいけないこと

- 検査するファイルに書き込まない（読むだけ）。問題を見つけても、直さない
- 外部と通信しない
- 自己試験で、自分が作った一時フォルダ以外のものを消さない
- 読めなかったファイルを、「問題なし」「問題あり」のどちらかに丸めない

## 使う部品

**追加の部品（パッケージ）は要りません。** zip と XML を読む機能が標準で付いている言語なら、
標準の機能だけで作れます（Python なら `zipfile` と `xml.etree.ElementTree`）。
部品を足したくなったときは、`.claude/skills/program-writing/SKILL.md` の STEP 1 に従い、
1つずつ社長の了承を得てください。

## Windows と Mac の注意

- 画面への出力は UTF-8 にそろえます（Windows では、指定しないと日本語が化けることがあります）
- ファイルのパスに、日本語や空白が入っていても動くようにします
- Mac では、Python の呼び出しが `python3` になることがあります

## 作り方の手順

1. `.claude/skills/program-writing/SKILL.md` を読み、その作法に従って書きます
2. 置き場所は `Programs/xlsx-check/` です（`Programs/README.md` の決まりに従い、場所を `CLAUDE.md` に書き足します）
3. `tests/cases.json` の全ケースを実行し、**すべて合格するまで直します**
   （実行の決まりは `Programs/specs/README.md`「テストの実行の決まり」）。
   合格しないケースを、ケースの側を書き換えて合格にしないでください
4. 自己試験（`--selftest`）にも、問題のないファイル・問題のあるファイル・読めないファイルを入れます
5. 書いた本人以外の目（経緯を知らない別の AI など）に、この仕様とプログラムをそのまま読ませ、
   「読めないものを合格にする道」「シートを見ずに合格にする道」が残っていないかを見てもらいます。
   指摘を直したら、もう一度読ませます
6. 作ったプログラムの先頭に、「仕様のバージョン：1」と書いておきます（仕様が新しくなったときに、作り直すかを判断するため）

## 限界

- **終了コード 0 は、「Excel で必ず問題なく開ける」という保証ではありません。**
  見ているのは上の3つの型だけです。大事なファイルは、渡す前に Excel で1回開いて確認してください
- 数式の誤り・金額の誤り・見た目の崩れは見ません
- `.xls`（古い形式）と、パスワードの付いたファイルは読めません（終了コード 2）。
  「Strict Open XML スプレッドシート」の形式で保存したファイルも読めません（終了コード 2）
- 問題を見つけるだけで、直しません
- テストの材料は、判定に必要な最小の部品だけを入れた作り物です。Excel で開くためのファイルではありません
