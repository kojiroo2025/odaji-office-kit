# オフィス開設キット

ニュースレター「一人社長とAI従業員」の準備編（第2号から第12号）で作ってきたファイルを、
一式まとめたものです。会社ごとに違うところは空欄にしてあります。
**AI従業員の質問に答えていけば埋まります。**

---

## この1枚の読み方

**前半だけ読めば、始められます。** 後半は、始めたあとで必要になったときに読んでください。

| | 何が書いてあるか | いつ読むか |
|---|---|---|
| **前半** | このキットで何が手に入るか／使う前に要るもの／**入れ方**／何が起きるか | **いま** |
| 後半 | 中に入っているものの一覧／入っていないもの／更新のしかた／保守／免責・ライセンス | あとで |

**すぐ始めたい方は、「入れ方」まで飛ばしても構いません。**
飛ばしても危ないことは起きません。前半のそれまでの部分は、説明だけです。

---

## このキットは、オフィスを整えるものです

名前のとおりです。**オフィスを「開設」します。従業員を雇うのは、そのあとです。**

Claude Code は、そのままでも動きます。ただ、**あなたの会社のことを何も知りません。**
会社名も、住所も、書類の決まりも、やってはいけないことも。
だから最初は、頼むたびに説明し直すことになります。

このキットは、**その説明を1回で終わらせるための一式**です。
入れ終わると、あなたのオフィスはこうなります。

- 会社のことを知っている（社名・住所・連絡先・ロゴ・会社の色）
- **鍵になるファイルが読めない**（サービスに接続するIDやパスワードが入ったファイル）
- **データを直接インターネットへやりとりする操作が止まる**
- 文章の書き方が決まっている（AIっぽい文章になりません）
- 仕事の進め方と、報告のしかたが決まっている

**次の2つは、お使いのパソコンによって、初日に手に入るかどうかが変わります。**

| | どうなるか |
|---|---|
| **消したファイルを元に戻せる**（`Git` の控え） | **`Git` が入っていれば、初日に控えを1つ取ります。**入っていなければ、あとから入れたときに取ります。**控えを自動で取り続ける仕組みは、続きの回で作ります**（後半の「初日の控えは、1回きりです」） |
| **強制的にまとめて消す操作が止まる** | **`Mac` では止まります。Windows では止まりません**（理由は後半の「1つだけ、はっきり書いておきます」に書いています） |

**どちらも、開設の日にAI従業員が確かめて、あなたのパソコンではどうなのかを伝えます。**
**推測でお伝えすることはありません。**

**この状態を、AI従業員をいつ雇ってもよい状態と呼んでいます。**
1人目を雇うのは、ニュースレターの実践編（次の号から）です。
**このキットは、そこまでは踏み込みません。**

> **相手は、はじめから終わりまで1人です。**
> パソコンに入れた `Claude Code` のことを、**この説明書では「AI従業員」と呼びます。**
> 開設の作業をするのも、そのあと仕事を覚えるのも、同じ相手です。
>
> **「1人目を雇うのはあと」というのは、人が増えるという意味ではありません。**
> **あなたの商売に固有の仕事を覚えさせるのが、あと**という意味です。

**このキットは、種であって、完成品ではありません。** それだけでは何もしません。
**中身に、あなたの会社のことが1つも書かれていないから**です。

中身を埋めるのはあなたとAI従業員で、埋め終わったときには
「小田島が配ったキット」ではなく「あなたの会社のオフィス」になっています。

## あなたはどれに当てはまりますか

> ### その前に　もうこのキットを入れてある方へ
>
> **1回入れた方、途中でやめた方は、ここで止まってください。**
> **「入れ方」は、もう要りません。読まないでください。**
>
> **やることは1つだけです。** Claude Code で**そのフォルダを開き**、次の文を貼ってください。
>
> ```
> オフィス開設の続きをやりましょう。
> いまどこまで終わっているか、進捗の表を見せてください。
> ```
>
> **前に答えたことは、聞き直されません。**進捗の表に残っているからです。
> **答えた覚えがあいまいなものは、AI従業員に聞いてください**
> （例：「削除の設定は、いまどうなっていますか」）。
>
> **ただし、表は「AI従業員が埋めたところまで」しか映していません。**
> 答えた直後に閉じた場合、そのぶんが表に入っていないことがあります。
> **表を見たら、「設定ファイルの中身も見て、表と合っているか確かめてください」と頼んでください。**
> **表だけを信じないでください。**
>
> **やってはいけないこと＝もう一度ダウンロードして、同じ場所に置き直すこと。**
> **あなたが答えた会社名も、禁止事項の設定も、空のキットで上書きされます。**
> **新しい版が出たときも、置き直しません**（後半の「新しい版が出たとき」に、正しいやり方があります）。

**ここから先は、はじめて入れる方の話です。**

**入れ方は「A」と「B」の2つです。どちらかは、次の1問で決まります。**

> **Claude Code で毎回同じフォルダを開いて、そこに仕事のファイルを貯めていますか。**

| 答え | 入れ方 |
|---|---|
| **いいえ／よく分からない** | **A**（入れて起動してみただけの方、準備編を読んだだけの方は、こちらです） |
| **はい** | **B** |

**迷ったら A です。**

> **A で始めたあとに「そういえば、別のフォルダで使っていた」と思い出したときは、
> そのことをAI従業員に伝えてください。** その場で B のやり方に切り替えられます。
> **そこまでの作業は無駄になりません。**
>
> **AI従業員のほうからは気づけません。** 開いたフォルダの外が見えないからです。
> **思い出したら、言ってください。**

**手順2から先は、AとBで違います。** 得られるものは、次のとおりです。

| あなたの状況 | 何が起きるか |
|---|---|
| Claude Code を入れたばかり | **いちばん得をします。** 手間のかかる初期設定を、ほとんど飛ばせます |
| 準備編を途中まで進めた | 作った分はそのまま残り、**足りないところだけが埋まります** |
| すでに自分でひととおり作ってある | **点検に使えます。**「**このキットにあって**、お手元に無いもの」が一覧で出ます。当てるかどうかは、**あなたが1件ずつ決めます。勝手には変えません** |

中身は、**Claude Code を作っている会社（Anthropic）が公式に示している標準の形**に沿って作り、
そこに**公開されている研究や論文から取り入れた知見**を足しています。

## 使う前に

**必ず要るものは、ひとつだけです。**

**Claude Code がパソコンに入っていて、1回起動したことがあること。**

**あるともう1つ手に入るもの＝Git**（第9号でお伝えした、変更履歴の仕組み）。
**入っていなくても、開設は最後まで進みます。**
入っていれば、**その日の状態に戻せる控えを1つ**、同じ日に取ります。
入っていなければ、AI従業員がその場でそう伝えます。**あとから入れても大丈夫です。**

> **先に Git を入れる必要はありません。そのまま始めてください。**
> 入っているかどうかは、AI従業員が開設の日に確かめて教えてくれます。
> **入れるかどうかは、そのとき決めれば間に合います。**

まだの方は、先に第2号を読んでください。インストールと初回起動だけで済みます。
20分ほどです。**このキットの手順は、そこから先だけを書いています。**

第2号：https://odaji-ai.m-newsletter.com/posts/solo-ceo-ai-employees-difference

**あると早く進むもの**（無くても進められます）

- 会社のホームページのURL、または名刺1枚（写真で構いません）
- 会社のロゴの画像
- 会社の色（決まっていれば）

> **いまあるファイルは、触りません。**
> Claude Code は、**開いたフォルダの中だけ**を自分の持ち場とします。
> このキットで開くのは、**新しく作るフォルダ1つ**だけです。
>
> **そのフォルダの外にあるもの（あなたの書類・写真・メール）に手を伸ばすときは、
> 必ずあなたに確認が出ます。**
> **公式ドキュメントにそう書かれています**（持ち場の外を読むとき・書き換えるときは、
> そのつど許可を求める、という決まりです）。
>
> **「絶対に届かない」ではありません。「黙っては届かない」です。**
> **だから、外のフォルダの名前が出ている確認だけは、読んでから答えてください。**
> 開設の作業で、AI従業員のほうから外へ手を伸ばすことはありません。

# 入れ方

**つまずきやすいところを、細かく書きます。** 分かっている方は飛ばしてください。

> ## 画面で迷ったら、AI従業員に聞いてください
>
> **この説明書に書いていない画面が出ることがあります。** お使いのパソコンや、
> アプリの版によって、言葉や並びが少しずつ違うからです。
>
> **そのときは、止まらずに、Claude Code の文字を打ち込む欄に、
> 見えているものをそのまま書いてください。**
>
> 　例：「いま『このファイルは安全でない可能性があります』という表示が出ています。
> 　どこを押せばよいですか」
>
> **文字で書けば通じます。画面を見せる必要はありません。**
> 見せたいときは、**`Windows` キー（旗のマークのキー）と `Shift` と `S` を同時に押し**、
> 見せたいところをマウスで囲みます。
> 打ち込む欄で **`Ctrl` を押しながら `V`** を押すと貼れます。
>
> **手順3より前（ダウンロードや展開の途中）でも聞けます。**
> Claude Code を起動して、フォルダを選ばずにそのまま質問して構いません
> （**どこか適当なフォルダが開いた状態で構いません。**
> 質問に答えるだけなら、フォルダの中身は関係ありません）。
> 「オフィス開設キットを入れようとしています」と添えれば、話が通じます。
>
> **ただし、この逃げ道が使えない場面が2つだけあります。**
>
> | 場面 | どうするか |
> |---|---|
> | **Claude Code を起動する前**（起動そのものがうまくいかない） | **第2号に戻ってください。**起動の手順はそちらにあります |
> | **`Yes` と `No` の選択肢が画面に出ているとき**（英語のコマンドの文字が一緒に出ます） | **原則は `Yes` で始まるほうです**（理由と、**2つの例外**は、下の「途中で『よろしいですか』と何度も聞かれます」に書いています。**そこだけは先に読んでください**）。**AI従業員が日本語の文で「〜してよろしいですか」と聞いてきたときは、これに当たりません。ふつうに答えてください** |
>
> **この2つ以外は、すべて聞けます。**

**押す場所を1つずつ書きます。**
**入れ方の中で打ち込むのは、「手順4」（Bの方は「手順5」）の枠1つだけ**です。
それも、**この説明書からコピーして貼り付けるだけ**で、考えて打つ必要はありません。

**そのほかの枠は、いま貼るものではありません。**「困ったときに、こう言えば通じます」
という言い方の見本なので、**その場面が来たときに使ってください。**

（入れ方が終わって開設が始まると、会社名や住所を答えるなど、
ふつうに文字を打つ場面があります）

### 途中で「よろしいですか」と何度も聞かれます　←　先に読んでおいてください

AI従業員がファイルを書いたり、設定を変えたりするたびに、
**Claude Code 本体が、あなたに確認を求めます。** 画面に、実行しようとしている
操作の文字と、選択肢が出ます。**何十回も出ます。**

### まず、2種類あることを知ってください

**見た目は似ていますが、別物です。答え方も違います。**

| | どういうものか | どうするか |
|---|---|---|
| **① 窓で出る確認** | Claude Code が出すもの。**英語のコマンドの文字と、`Yes`／`No` の選択肢**が出ます | **開設中は、すべて許してください** |
| **② AI従業員が日本語で聞いてくるもの** | 会話の中に、ふつうの日本語の文で出ます（「〜してよいですか」「どちらにしますか」） | **読んで、考えて、答えてください** |

**②は、あなたが決めるべきことです。**
禁止事項を足すとき、設定を変えるとき、フォルダを作るとき、AI従業員は**必ず日本語で説明してから聞きます。**
**そこは、飛ばさずに読んでください。**

**以下は、①の話です。**

### ①の確認は、開設の作業中はすべて許してください

> **これは、A の方に向けた話です。**
>
> **B の方（すでにあるオフィスに足す方）は、当てはまりません。**
> **B の方は、①も読んでから答えてください。** 理由は「B　すでにあるオフィスに足す」に書いています。
> **あなたのフォルダには、あなたの仕事のファイルが入っているからです。**

**迷う必要はありません。**

**そう言い切れる理由があります。**

> **禁止に書いてある操作は、①の確認すら出ません。** その場で止まります。

**そして開設の日は、AI従業員のすることが `START_HERE.md` の手順だけに決まっています。**
①で出るのは、その手順の中身です。おもに次の4つです。

- このフォルダの中にファイルを書く
- 設定ファイルに文字を書き込む
- **`Git` の控えを始める**
- **あなたの会社のホームページを読み取る**（会社情報を埋めるときに1回）

**「何を書き込むか」は、その前に②であなたに聞いています。**

> ### ただし、2つだけ例外があります
>
> **この2つに当てはまる確認が出たら、許さずに、そこで止めてください。**
>
> | どんなとき | なぜ止めるのか |
> |---|---|
> | **窓の文字に、このオフィスのフォルダの外の場所が出ている** | **見分け方は1つです＝`AI_Office` という文字が入っていない場所**が出ていたら、外です。**開設の手順に、外へ手を伸ばす作業はありません** |
> | **AI従業員が「禁止が効いているか試します」と言った直後に、窓が出た** | **その試しは、窓が出ずに止まるのが正しい動きです。**窓が出たなら、**禁止が効いていません** |
>
> **あなたのオフィスの場所は、こう書かれます。**
>
> | | オフィスの中（許してよい） |
> |---|---|
> | **Windows** | `C:\AI_Office\` で始まるもの |
> | **Mac** | `/Users/〈あなたの名前〉/AI_Office/` で始まるもの |
>
> **Mac の方へ。** オフィスの場所にも `Users` という文字が入っています。
> **`Users` が出ただけでは、外ではありません。**`AI_Office` が入っているかどうかで見てください。
>
> **いちばん最初に出る「このフォルダを信用しますか」の窓は、これに当たりません。**
> **そこに出ているのは、オフィスそのものの場所です。許してください。**
>
> **どちらも、`No` を選んで、AI従業員にそのまま伝えてください。**
>
> 　例：「いま出た確認に〈見えている文字〉と書いてあったので、断りました。これは何ですか」
>
> **窓が出ているあいだは、文字を打つ欄が使えません。**
> **先に `No` を押してから、聞いてください。**

> **開設が終わったあとは、話が変わります。**
> 禁止に書いていない操作にも、危ないものはあります。
> **そこを止める役目を持っているのが、①の確認です。**
> **ふだんの仕事に入ったら、①も読んでから答えてください。**
> **「すべて許してください」と言えるのは、開設の日だけです。**
>
> **「続きの回」も、開設の日には入りません。**
> 続きの回には、**鍵をオフィスの外へ移す**作業と、**控えを外へ預ける**作業が入ります。
> **どちらもオフィスの外に出る操作です。**
> **続きの回に入ったら、①も読んでから答えてください。**

**どれが「許す」か**

| | 日本語で出たとき | 英語で出たとき |
|---|---|---|
| **許す（こちらを選ぶ）** | 「はい」「許可」で始まるもの | **`Yes` で始まるもの** |
| 断る | 「いいえ」で始まるもの | `No` で始まるもの |

**許す側は、たいてい上に並んでいます。**「今回だけ」「今後も聞かない」のように
許し方が何通りか出ます。**どれでも構いません。**
「今後も聞かない」を選んでも、**禁止事項に書いた操作は止まったまま**です。

### 断るのは、開設が終わったあとです

ふだんの仕事に入ってから、**「これは頼んでいない」と思う確認が出たとき**が、断る場面です。

**断っても壊れません。** AI従業員に「実行できませんでした」と伝わり、**会話はそのまま続きます。**
それまでの作業が取り消されることもありません。そのうえで、こう聞けます。

```
いま何を聞かれていましたか。日本語で説明してください。
```

説明を聞いて納得したら、**「さきほどの操作をやり直してください」と言えば、続きます。**

## 手順1　ダウンロードする（A・B 共通）

ニュースレターに載せたリンクから、**配布ページ**を開いてください。

**ページを下へたどっていくと**、**`AI_Office.zip`** というファイル名のリンクがあります。
それを押すと、いつものダウンロードの場所（多くは「ダウンロード」フォルダ）に入ります。

> **配布ページは英語です。** 読む必要はありません。
> **押すのは `AI_Office.zip` という文字、1か所だけ**です。
>
> **似たものが、同じページに並んでいます。押さないでください。**
> **並ぶ場所は、ページの作りによって変わります。上にあることも、下にあることもあります。**
>
> | 押さないもの |
> |---|
> | **`Source code (zip)`** |
> | **`Source code (tar.gz)`** |
> | 緑色の **`Code`** というボタン（出ていないこともあります） |
>
> **目印は、`Source` という文字が付いていないこと**です。
> どれも似たものが手に入りますが、**フォルダの名前と中の並びが違うものになり、
> このあとの手順が合わなくなります。**

> **押したら、名前を確かめてください。**
> 「ダウンロード」フォルダに入ったファイルの名前が **`AI_Office`**
> （または `AI_Office.zip`）であれば、正しく押せています。
> **`odaji-office-kit` のような別の名前だったら、押し間違いです。**
> そのファイルを削除して、もう一度ページへ戻ってください。
>
> **見つからないときは、AI従業員に聞いてください**（この「入れ方」の冒頭に書いた方法です）。

> **押したあと、ブラウザが「このファイルは安全でない可能性があります」
> 「一般的にダウンロードされていません」などと止めることがあります。**
> ZIPファイルではよくあることです。**「保存」「続行」「保持する」にあたるほうを
> 選んでください。** 言葉はブラウザによって違います。
> 迷ったら、出ている言葉をそのまま書いて、AI従業員に聞いてください。

> **`AI_Office.zip` を人から直接もらった方**は、この手順1は要りません。
> もらったファイルを使って、手順2へ進んでください。

## A　新しくオフィスを作る

**Mac をお使いの方は、次の「手順2（Mac をお使いの方）」まで飛ばしてください。**

### 手順2　展開して、`C:` の直下に置く（Windows）

**2つに分けます。まず展開し、次に移します。**

#### ① 展開する

1. 「ダウンロード」フォルダを開きます

## 何が起きるか

### その日のうちに終わること

まず、**禁止事項が本当に効いているかを、その場で1回試します。**
AI従業員が、わざと「やってはいけない操作」を1つ実行してみせ、
**止まるところをあなたに見せます。**「実行できませんでした」という表示が出ますが、
**それが正しい動きです。** 先にひとこと声をかけてから試します。

> **このときは、あなたに「よろしいですか」は出ません。**
> 禁止した操作は、**確認を出すより前に止まる**からです。
> **あなたが何かを押して止める必要はありません。** 見ているだけで大丈夫です。
>
> **この試しでは、ファイルは1つも作られません。** 試す操作は決めてあり、
> 実行される前に止まるものを選んであります。**あとから消す手間はありません。**
>
> **万が一、止まらずに実行されてしまったときは、そこで作業を止めてください。**
> 設定が効いていないということなので、AI従業員に
> 「禁止が効いていません。原因を調べてください」と伝えてください。

**次に、変更履歴（Git）を始めて、実際に戻せるところをお見せします。**
AI従業員が、**いらないファイルを1つ作って、消して、元に戻します。**
**Claude Code の画面には、やったことが文字で出ます**（フォルダを開いて並べておけば、
そちらでも現れて消えるのが見えます）。**それが正しい動きです。**
（さきほどの「ファイルは1つも作られません」は、**その前の禁止の試し**についての話です）

**Git が入っていないパソコンでは、この実演はできません。**
そのときは、AI従業員が「変更履歴はまだ始められていません」と正直に伝えます。

そのあと、**何が変わったかの報告**（3点だけ、15行ほど）が来て、
続けて**業務上の判断を1つ**聞かれます。技術的な質問ではありません。こういう形です。

> いまの削除の止まり方を、お伝えします。
> 消えたものを戻せるかどうかも、あわせてお伝えします。
> （1）このままにする　（2）ファイルの削除を、私にはできないようにする

**前半の文は、お使いのパソコンによって変わります。**
`Mac` なら「強制的にまとめて消す操作は止まっています」、
Windows なら「削除は1つも止まっていません」と伝えられます。
**理由は、後半の「1つだけ、はっきり書いておきます」に書いています。**

**ここでいう削除は、このオフィスのフォルダの中にあるファイルのことです。**
ドキュメントやデスクトップにあるあなたの書類は、AI従業員の持ち場の外にあります
（**触るときは、必ずあなたに確認が出ます**）。

**迷ったら（1）で構いません。** あとから変えられます。

**ただし「`Git` がまだ入っていません」と一緒に伝えられたときは、（2）も考えてください。**
**削除を止めるものが1つも無く、消えたものを戻す手だても無い、という状態だからです。**

（2）を選ぶと安全は増えますが、**このフォルダの中で要らなくなったファイルを消す作業が、
すべてあなたの手作業になります。**（並べ替えやフォルダ分けは、どちらを選んでもAI従業員がやります）

**（2）を選んでも、完全ではありません。** 別の書き方で通る道は残ります
（後半の「禁止事項は、万能ではありません」）。**うっかり消える事故は、ほぼ防げます。**

そのあと、会社のこと（社名・住所・連絡先・ファイルの保存場所・ロゴと色）を聞かれます。

**ゼロから考える必要はありません。** どれも、AI従業員が先に案を出してから
「これでよろしいですか」と聞く形です。**違うところだけ言えば済みます。**
**ロゴや色がまだ決まっていなくても大丈夫です。** 「あとで」と答えれば先へ進みます。

ここまでで、だいたい30分から1時間です。

**終わると、オフィスが整った状態になります。**
AI従業員は、そこで作業を終えて、次のご指示を待ちます（固まったわけではありません）。
**Claude Code は、そのまま閉じて構いません。** 入れたものは全部フォルダに残ります。

### 禁止事項は、最初から効いています

`.claude/settings.json` には、**どの会社でも止めてよいものだけ**を入れてあります。

- **管理者の権限で実行しようとする操作**（`sudo`。Mac・Linux の仕組みです）
- **データを直接インターネットへやりとりする操作**（`curl`・`wget` などの道具を使うもの。
  送るのも、取りに行くのも止まります）
  **※ AI従業員がウェブページを読むのは、別のやり方です。止まりません**
  （会社のホームページを読み取るときは、確認が1回出ます。許してください）
- **Git の控え**を、インターネット上の保存場所へ強引に上書きする操作
  （控えをインターネット上にも置くようになったときに効きます。
  いまは置いていないので、何も起きません）
- 鍵になるファイルを読むこと（サービスに接続するためのIDやパスワードが入ったファイル）

> **お金を動かす操作は、まだ入っていません。**
> 会計ソフトや銀行につないでいないうちは、**そもそも道がないから**です。
> **つなぐときに足します。** その手順は `.claude/skills/connect-check/` が担当します。

> **どこまで止まるかは、お使いのパソコンによって変わります。**
> Claude Code は、パソコンによって命令の出し方が変わります。
> **`Mac` では `Bash`、`Windows` では `PowerShell` という道具を使います。**
> Windows に `Git` を入れると `Bash` も使えるようになりますが、
> **`PowerShell` が使えなくなるわけではありません。両方が使える状態になります。**
> **禁止は道具ごとに書いてあるので、片方にしか書いていない行は、もう片方から通ります。**

### 1つだけ、はっきり書いておきます

**「強制的にまとめて消す操作」は、上の一覧に入っていません。**

**止まるのは `Mac` だけです。Windows では止まりません。**
**`Git` を入れていても同じです**（`PowerShell` のほうから通ってしまうためです）。

> **これは、禁止事項の書き方から言えることです。**
> **そのうえで、開設の日に、AI従業員があなたのパソコンで実際に試して、
> 止まるところ（または止まらないこと）をお見せします。**
> **書いてあることを信じてください、とは言いません。**

**書き方を揃えて両方を塞ぐ方法が、うまく作れませんでした。**
`PowerShell` の削除は、同じ操作を何通りにも書けるためです。

**そこで、こうしています。**

1. **開設の日に、AI従業員があなたのパソコンを確かめて伝えます**
2. **Windows だったときは、「削除そのものを止めますか」とその場で聞きます。**
   **止めると答えれば、その場で足します**（ふだんのファイル整理は、あなたの手作業になります）
3. **削除に対する本当の備えは、`Git` の控えです。**
   **`Git` が入っていれば、控えを取った時点まで戻せます。入っていなければ、戻せません。**
   **どちらなのかも、開設の日にAI従業員が伝えます**

### 初日の控えは、1回きりです

**`Git` が入っていれば、開設の日に控えを1つ取ります。**
**そこまでは戻せます。** ただし、**そのあと自動で控えを取り続ける仕組みは、まだ入っていません。**

その仕組み（フック）は、**続きの回で作ります**（進捗の表の⑭）。
**それまでのあいだに作って消したものは、戻りません。**

**大事なものを直す前に、こう頼んでください。**

> いまの状態を、変更履歴に控えておいてください。

**これは開設の日でも、続きの回の前でも、いつでも頼めます。**

### 禁止事項は、万能ではありません

**ここは、正直にお伝えしておきます。**

禁止は「**このコマンドの、この書き方**」を止める形で書かれています。
**同じことを別の書き方で頼めば、通ってしまう道が残ります。**
たとえば、フルパスで呼ぶ、別の道具を使う、プログラムの中から実行する、といった形です。

**それでも、お願いだけの状態とは安全性が段違いです。**
禁止に書いた操作は、**確認の画面すら出さずに止まります。**

**大事なのは、禁止に頼り切らないことです。**

- **鍵になるファイルを、オフィスのフォルダの中に置かない**（そもそも読ませない）
- **つないでいないサービスは、つながない**（道を作らない）
- **消したものが戻せる状態にしておく**（Git の控え）

**見張って止めるより、道を断つほうが強いです。**
この考え方は `.claude/settings-template.jsonc` の終わりにも書いてあります。

**あなたの会社に合わせた禁止事項は、開設の最初に足します。**
何を足すかの考え方と書き方は `.claude/settings-template.jsonc` に書いてあります。

**最初から効かせている理由は1つです。** 開設の話が終わってから設定する形にすると、
**いちばん最初のセッションだけ、守りが無い状態になります。**
そこは、AI従業員がファイルをいちばんたくさん書く場面です。

## 入っていないもの

3つあります。理由も書きます。

### 1. あなたの商売に固有の仕事

見積もりのチェック、問い合わせへの返信、日報の整理。
こうした「あなたの会社ならではの仕事」は入っていません。

これは**入れられなかったのではなく、入れませんでした。**
他社の仕事の手順をそのまま持ってきても、あなたの会社では使えないからです。
ニュースレターの実践編で、1人ずつ一緒に作っていきます。

### 2. フック（第10号でお伝えした「必ず実行させる」設定）

**フックとは、決めた場面で必ず自動的に実行される設定です。**
AI従業員が忘れても実行されるところが、お願いとの違いです。

**この版には入れていません**（できあがったファイルとしては同梱していません）。
このキットは「実際に動かして確かめたものだけを配る」方針で作っており、
フックはお使いの環境によって動きが変わるため、まだ確かめ切れていないからです。

**そのかわり、開設の「続きの回」で、あなたの環境に合わせて2つ作ります**（進捗の表の⑭と⑮）。
**次の版を待つ必要はありません。**
作業の区切りで **Git の控え**を残すものと、`CLAUDE.md` が200行に近づいたら知らせるものです。

### 3. バックアップの仕組み（第9号）

あなたのGoogleアカウント、あなたのフォルダ、あなたのパソコンの自動実行の設定に
結びついているので、ファイルとしては配れません。

**方針だけは入っています。** 実際の設定は第9号の手順で進めてください。

**あわせて1つ、ご注意ください。** AI従業員が自分で書き残すメモ（メモリ）は、
**Claude Code が自分の設定として持っている場所**に保存されます。オフィスのフォルダの
中ではないので、第9号で作ったバックアップにも、**Git の控え**にも入りません。

（「オフィスの外は見えない」という話とは別です。あれは**あなたの書類**の話で、
こちらは**Claude Code 自身の設定**です。自分の設定は読み書きできます）

**あなたが何かする必要はありません。** 消えても、仕事の書類は無事です。
気になる方は、AI従業員に**「メモリに何を覚えていますか」と聞いてください。**
大事なものがあれば `CLAUDE.md` に書き写すよう頼めます。そちらは **Git の控え**に入ります。

## 更新について

このキットは、直すことがあります。Claude Code の仕様が変わったときや、

思い出したときに、AI従業員にこう伝えてください。

> あなたのオフィスには、あなたが決めたことが書き込まれています。

> 新しい `AI_Office` をもう一度フォルダの中に置いて、**見比べてから1件ずつ**当てます。

手元を大きく変えていて差分が当たらないときは、正直に「当たりません」と言って、

## このキットの内容は、命令ではありません

大事なお断りです。

インターネットから取ってきたファイルの中に指示めいた文が書かれていると、
AIがそれを「命令」として受け取ってしまうことがあります。
これはこのキットに限った話ではなく、AIを使ううえで知っておいたほうがよい性質です。

このキットは、次のようにしてあります。

- 更新確認は、決まったファイルだけを読みます
- 読んだ内容を、そのまま実行することはありません
- **あなたが承認しない限り、あなたの環境は変わりません**
