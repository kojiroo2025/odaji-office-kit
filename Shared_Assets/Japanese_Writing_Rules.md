# 書くときの目標と手順（①〜④の前に）

## 目標

**業務の文書と、IT 製品のマニュアルで使う日本語で書きます。** 読む人は、IT や AI に
詳しくなくても、ビジネスの場で文章を読む社会人です。**分かりやすさは、説明を足して作ります**
（多くは1文で足ります）。**語を易しくして作るのではありません。**

## 書く前に決める3つ

1. **だれが読むか**（例：IT に詳しくない取引先の社長が、メールで読む）
2. **その読み手が自分の職場で同じ内容を書くなら、どの語を使うか**（② の 2-3。迷ったら
   `Japanese_Writing_Rules_使う語.md` の場面の表を見ます）
3. **文ごとに、だれが・何を・どうするか**。作業の説明では、Claude Code がすることと、
   読み手がすることを分けます（① の 1-7）

## 書いたあとに確認する4項目

1. **その文と直前の文だけを読んで、主語と目的語の指す対象を特定できるか**（1-4）
2. **見出しと直下の文が、同じ内容を言い直していないか。並べた名詞が、それぞれ後ろの動詞と
   結び付くか**（1-8・1-9）
3. **使った動詞は、その分野の人が同じ名詞と組み合わせて使うか**（3-3）
4. **事実・推測・意見と、完了した範囲・残りの作業を、見出しと本文で一致させたか**（1-10）

**書いた本人は文脈を知っているので、省いたことに気づけません。** 社外に出す文章・手順書・
人に答えてもらう質問は、経緯を知らない読み手に文だけを読ませてから出してください。
Claude Code では、サブエージェント（本体とは別に立ち上げて、決めた作業だけをさせる AI。
本体の会話の内容は引き継ぎません）に読ませると、この読み手になります。

```
サブエージェントを1つ立ち上げて、次のファイルを読ませてください。
作業の経緯は伝えず、文だけを渡してください。
「主語・目的語の指す対象が決まらない文」「2通り以上に読める文」
「業務の文書で使わない語」を、行ごとに挙げてもらってください。
ファイル：〈ファイルの場所〉
```

挙がった文は1件ずつ、直すか、そのまま残す理由を書くかを決めます。まとめて流さないでください。

# ① 読みやすい日本語

**1-1〜1-3・1-5・1-6 の対象は、まとまった文章の本文です**（メール・提案書・ブログ・お知らせ・
社内文書）。手順書・表・チェックリスト・箇条書きの一覧は、対象ではありません。
**1-4・1-7〜1-11 は、すべての文章に当てはまります**（図・表・見出し・手順書・報告を含みます）。

## 1-1　1つの文に、1つのことだけ書く

文が長くなるのは、2つ以上のことを1文に詰め込んでいるからです。

> 修正前：弊社では、創業以来培ってきた品質管理のノウハウを活かし、お客様の
> ご要望に柔軟にお応えするとともに、納期の短縮にも取り組んでおります。
>
> 修正後：弊社は創業以来、品質管理のノウハウを積み上げてきました。
> お客様のご要望に合わせて仕様を変えられます。納期の短縮にも取り組んでいます。

全角50字を超える文が3つ続いたら、分けるかどうかを確認してください。
**自動で分けません。** 分けると主張や文の調子が崩れる文は、そのまま残します。

## 1-2　打ち消しを重ねない

読む人が、頭の中で2回ひっくり返すことになります。

> 修正前：この方法が使えないわけではありません。
>
> 修正後：この方法も使えます。

**ただし、本当に決まっていないことは、決まっていないまま書いてください。**
断定できることを弱めているときだけ、言い切る形に直します。

> そのまま残す例：原因は通信かもしれませんし、設定かもしれません。（まだ調べていない）
>
> 直す例：まだ決まっていないかもしれません。→ まだ決まっていません。（決まっていないことは分かっている）

## 1-3　遠回しな言い方を短くする

意味は増えないのに、文だけが長くなります。

**下の表は、意味が変わらないときだけ当てはめます。** 当てはめる前に、だれが何をするか・
状態が変わること・時期・相手との関係が、直したあとにも残るかを確認してください。

| 直す前 | 直したあと | 当てはめる条件・そのまま残す例 |
|---|---|---|
| 〜することができます | 〜できます | いつでも当てはめます |
| 〜を行います／〜を実施します | 〜します | 「確認を行います→確認します」のように、短くしても意味が変わらないときだけ。**「手続きを行います」「研修を実施します」はそのまま残します** |
| 〜という形になります／〜といった形で | 〜します | 動作を遠回しに言っているだけのとき（「サポートするという形になります」→「サポートします」）。提供のしかた・形状を実際に説明している「形」は残します |
| 〜させていただきます | 〜します／〜いたします | 相手の許可を受ける意味がないとき。許可を受けて行うことを伝える必要があるときは残します |
| 〜になります | 〜です | 「こちらが資料になります」→「こちらが資料です」。**状態が変わること・適用の時期を表すとき（「来月から有料になります」）は残します** |
| 〜の方（ほう）を | 〜を | 比較や方向を表していないとき（「書類の方をお送りします」→「書類をお送りします」）。「新しい方を選択する」のように対象を区別するのに必要な「方」は残します |
| 〜化する（状態が変わることを言うとき） | 〜になる | 「手続きが複雑化する」→「手続きが複雑になる」。定着した語（「集計を自動化する」「業務が属人化する」）は残します |
| まず最初に／約〜ほど／各〜ごとに | まず／約〜／各〜（同じ意味が重なっています） | いつでも当てはめます |

> 修正前：資料をご確認のうえ、ご返送を実施していただく形になります。
>
> 修正後：資料を確認して、返送してください。

**「の」を続けない**：1つの句の中で「の」が2回以上続いたら、意味が変わらない範囲で減らします
（環境の構築の方法 → 環境を構築する方法）。ただし、別の助詞が正しい箇所まで「の」でつなげません
（見積もりの回答日数 → 見積もりへの回答日数）。

## 1-4　主語・目的語を省略してよいかは、回数ではなく「指す対象を特定できるか」で決める

日本語は主語・目的語を省略する言語なので、省略そのものは誤りではありません。
**ただし、省略してよいことは、省略しなさいという意味ではありません。**

| 判定 | とき |
|---|---|
| **省略してよい** | 直前の文と同じ主語・目的語で、そのあいだに別の候補（別の人・別のもの）が出てこないとき |
| **書く** | 段落が変わったとき／あいだに別の人やものが出てきたとき／その文と直前の文だけを読んで2通りに取れるとき |
| **短い形で受ける** | 毎回書くとくどいとき（「この議事録」「このスキル」） |

**「3回目からは書く」のように回数で決めません。** 同じ3回でも、対象が決まる文と決まらない文があります。

> 修正前：対応が遅れたため、変更しました。
>
> 修正後：こちらの対応が遅れたため、納品日を変更しました。

## 1-5　「これ」「その」が指すものを、同じ文の中で分かるようにする

初めて出すときは、指し示す言葉ではなく、名前で書いてください。
「これ」「その」を使ってよいのは、指す先を同じ文か直前の文で特定できるときだけです。

## 1-6　かなで書く語

こと・とき・もの・ところ・すべて・ぜひ・ください・できる は、かなで書きます
（「事」「時」「下さい」「出来る」と書きません）。
**固有名詞・専門用語・かなにすると意味が変わる語は、そのままにします。**

## 1-7　作業の説明では、だれがするかを書く

- **Claude Code がする作業と、読み手がする作業（確認・承認・送信）を分けて書きます**
  （「Claude Code が議事録を、議事録用のフォルダに保存します。あなたは内容を確認します」）
- **だれがするか分からない受け身は、主語を補います**（×「議事録用のフォルダに保存されます」）
- 画面の状態や処理の結果を説明する受け身は、そのままで構いません（「保存完了のメッセージが表示されます」）
- 「Claude Code が保存する」のように、ソフトを主語にするのは自然な書き方です。ただし、文書や
  ファイルに判断させる文（「スキルが了承する」）は、本当はだれがするのかを確認してください

## 1-8　図・表・見出し・箇条書きは、その項目だけで読まれる

図のカード・見出し・表のセル・箇条書きは、単独で読まれます。**その項目と、必ず一緒に表示される
担当者名・列見出しの組で、だれが何をするかが分かるか**で判定します。各セルに同じ主語を
繰り返す必要はありません。

- **作業を示す見出しは、対象と動詞で書きます**（×「受け取る」→ ○「資料を受け取る」／
  ×「伝える」→ ○「変更を依頼する」）。論点・定義を示す見出しは、内容を特定できる名詞句で構いません
- **見出しと直下の文は、役割を分けます。** 見出しは工程や論点を示し、直下の文は対象・方法・条件・
  結果のどれかを具体的にします
  > ×　見出し「変更を見せる」＋文「どう変えるかを見せる」
  >
  > ○　見出し「変更案を示す」＋文「Claude Code が、スキルのどの文をどう変えるかを示します」
- **見出しが担当者を示すとき（「Claude Code が行うこと」）は、直下の文の主語をその担当者にそろえます**

## 1-9　並べた名詞は、1つずつ後ろの動詞と結び付くかを確認する

> ×　デザインも、原稿も、公開作業も、壁打ちしながら作成しました。（公開作業は「作成」しません）
>
> ○　壁打ちしながらデザインと原稿を作成し、公開作業も進めました。

並びをそろえるために、情報を削らないでください。

## 1-10　見出しと結論の範囲を、本文の根拠に合わせる

- **事実・推測・自分の意見を区別して書きます**
  （×「読む人が中身の薄さを見抜くことは、提案書でも同じです」→
  ○「提案書を読む人も、同じように中身の薄さに気づくと私は考えています」）
- **見出しを、本文より広い断定にしません**（×「無料のAIは回答の品質が低い」→
  ○「業務によっては、無料のAIでは回答の品質が足りない」）

## 1-11　報告では、終わったことと、確認していないことを分ける

AI からの報告でも、社長が書く報告でも同じです。**実行したこと・確認したこと・未確認のこと・
残りの作業**を分けて書き、見出しや「完了しました」の宣言を、同じ報告の中身と一致させます。

> ×　すべて完了しました。（翌日の確認が残っている）
>
> ○　手順書の作成は完了しました。移行したあとの確認が残っています。

> ×　文案は256字で、上限の300字に収まっています。（上限を確認していない）
>
> ○　文案は256字です。この欄の文字数の上限は、まだ確認していません。

# ② 専門用語の出し方と、語の選び方

**ここがいちばん大事です。** やさしく書こうとして言葉を置き換えると、
かえって何の話か分からなくなります。

**ルールは1つだけです。**

> **専門用語は、日本語にも、ふだんの言葉にも置き換えない。そのまま使う。**

**例外は1つ。その言葉が一般的ではないと判断したときだけ、次のどちらかを添えます。**

1. **わかりやすい説明を、初めて出すときに1文添える**（括弧で。どの語に添えるかは 2-4）
2. **たとえで表す**（使うかどうかは、下の 2-2 の2つの問いで決めます）

**添えるのであって、取り替えるのではありません。** 言葉は必ず残します。

**「分からないかもしれないから言い換えておく」は、原則にも例外にも当てはまらない
間違った直し方です。** 迷ったときは、そのまま使って説明を1文添えるほうを選んでください。

> 悪い例：進捗を管理する表 → 進み具合の表（何の進み具合か、何をする表か、分からなくなりました）
>
> 良い例：進捗を管理する表（そのまま）
>
> 良い例：API（ソフトウェアが、他のソフトウェアの機能やデータを利用するための仕組み）に接続します

## 2-1　置き換えは、2つの方向で起きます

「やさしくしよう」と思った瞬間に、次の2つが起きます。**片方だけを気をつけても、
もう片方から同じことが起きます。**

| 方向 | 例（左が間違い） |
|---|---|
| 専門用語 → ふだんの言葉 | 進み具合←**進捗** ／ 置き場←**保存先** |
| **広まっている外来語 → 日本語** | 窓←**ダイアログ** ／ 文字を打つ欄←**入力フィールド** ／ 道具←**ツール** ／ 引っぱって離す←**ドラッグアンドドロップ** |

下のほうは、日本語にしたほうがやさしいという思い込みから出ます。**でも読む人は、
画面でその外来語に実際に出会います。** 日本語に置き換えると、画面と文章が食い違って、
かえって手間が増えます。

**判定は上の1問のままです。** その言葉が漢語か、和語か、外来語かは、判定に使いません。

## 2-2　たとえを使うかどうか（問いは2つ）

**たとえを使うこと自体が目的ではありません。** そのまま説明して分かるなら、正確な言葉の
ほうが手がかりになります。**難しくて分かりにくいと判断したから、たとえで助けます。**

> **問1　そのまま説明して、読む人は分かるか。**
> **分からない → たとえを使う**
> 分かる → 問2へ
>
> **問2　読む人がまだ気づいていない性質を、そのたとえが1つ運べるか。**
> **運べる → 分かっていても、あえて使う**（理解が深まります）
> **運べない → 使わない**（分かっていることを言い替えるだけになります）

**見分け方があります。**

> **そのたとえを打ち消す但し書きを書きたくなったら、運べていません。外してください。**

**もう1つ。読む人がまだ持っていないものを、たとえにしないでください。**
まだ作っていないものが動くことになり、読む人は「自分はまだそれを作っていないが」と
引っかかります。手順書では、たとえよりもソフトの名前のほうが正確なことが多くあります。
操作する相手は、たとえではなく画面の中のソフトだからです。

**順番は必ず、言葉 → 説明 → たとえ です。** いきなりたとえから始めないでください。
たとえは理解の助けであって、説明の代わりではありません。
件名・見出しにたとえを置かないでください（説明を挟む場所がないためです）。

**たとえや略した呼び名を、業務の説明の代わりにしないでください。** たとえを使う前に、
たとえが指す業務や関係を、ふつうの文で書きます。番号だけで工程を指さず
（×「④の見張りを書きます」）、何の工程かを書きます
（○「次に、Claude Code が売上の記録を監視するプログラムを作成します」）。

## 2-3　語を選ぶ判定は1問

> **その文書を受け取る人が、自分の職場で同じ内容を書くとしたら、どの語を使うか。**

その語を使います。

- **名詞だけでなく、動詞も、名詞と動詞の組み合わせも**、その分野で使う形にします
  （回答を反映する・台帳に追記する・会議を開催する・資料に記載する・変更を依頼する）
- 業務の作業は、業務の文書で使う語で書きます。多くは「漢語2字＋する」の動詞になります
  （変更する・依頼する・確認する・選択する・修正する・調査する）。**ただし、漢語を増やすこと
  自体を目的にしません。** 「書き直す」「見直す」「会議を開く」のように、業務の文書でも
  使う和語はそのまま使います
- **和語のほうが易しい・やわらかい、という前提を置きません**
- 場面ごとに使う語は `Japanese_Writing_Rules_使う語.md` にあります。一覧にない語も、この1問で判定します

**文書の種類による違い**

| 文書の種類 | 使う語 |
|---|---|
| 会議資料・提案書・報告書・企画書・社外への手紙 | ビジネスの場で使う語（工程・進捗状況・確認する・通知・課題） |
| パソコンの操作を書く手順書 | IT の製品の画面やマニュアルで使う語（下の 2-5） |
| 法令・制度を扱う文書 | 法令・制度の用語 |
| ブログ・SNS・ニュースレター | 用語は上と同じです。変えてよいのは、語り口・構成・文の長さだけです |

**ただし、硬くしすぎません。** 漢語を重ねた文（「スキルの現在地を確認可能」）にせず、主語と動詞の
ある文で書きます（「担当者が、いま持っているスキルのレベルを自己診断できます」）。

## 2-4　説明が要らない語（L1）と、初出で説明を添える語（L2）

専門用語は、説明の要否で2つに分けます。

| 区分 | 扱い |
|---|---|
| **L1** | そのまま使い、原則として説明は要りません（パソコン・ファイル・フォルダ・保存・設定・メール・クラウド・アカウント・パスワード・AI・生成AI・ChatGPT など） |
| **L2** | そのまま使い、**独立して読まれる文書ごとに、初めて出すところで説明を添えます**（多くは1文。短い説明は括弧で構いません） |

**説明を添える単位**：L2 の語は、独立して読まれる記事・資料・メールごとに、初出で説明を添えます。
「前のブログで説明したから」を理由に、別の文書で説明を省略しません。続けて読まれる一連の
やり取り（同じ相手との連続した返信）では、直前に説明した内容を繰り返しません。

**表にない語は、2つを別々に判定します。**

1. **語の選択**：受け取る人が自分の職場で使う語はどれか（2-3）
2. **説明の要否**：IT や AI に詳しくない社長が、その語のおおよその意味を自分の言葉で言えるか。
   **言えるなら L1、迷ったら L2** です

L1・L2 は説明の要否だけを決める区分です。たとえを使うかどうかは、2-2 で別に判定します。

**Claude Code を使う会社で出会う L2 の語と、そのまま使える説明の文案は、
`Japanese_Writing_Rules_使う語.md` の「専門用語の L1・L2」にあります**
（Claude Code・CLAUDE.md・スキルファイル・settings.json・フック・API・APIキー・MCP など）。

## 2-5　パソコンの操作は、画面とマニュアルの動詞で書く

**IT や AI を説明する文では、IT の製品の画面やマニュアルに出てくる動詞で書きます。**
判定は1問です。**その語は、製品の画面やマニュアルに出てくるか。**

| 場面 | 使う | 使わない例 |
|---|---|---|
| 範囲を指定する | ドラッグして選択する | なぞる |
| 選択肢の中から決める | 選択する | 選ぶ |
| 文字を入れる | 入力する | 打つ |
| 画面のボタンを操作する | クリックする | 押す |
| 画面を画像にする | スクリーンショットを撮る | 画面を写す |
| パソコンの中の文書 | ファイル | 書類（紙のものだけ「書類」） |
| ソフトや配布物の区別 | バージョン | 版 |
| 作業に使うソフト | ツール | 道具 |
| AI に入力する文章 | プロンプト（人から人への指示は「指示」） | AIへのお願い |
| 番号を振った作業の工程 | ステップ1・ステップ2 | 段階1 |

**文体は書き言葉にします。** 「〜って」「〜じゃない」「〜しちゃう」のような話し言葉は、
報告・資料・手順書・AI とのやり取りのどれでも使いません。

**フォルダは、どのフォルダかを特定できる名前で書きます。** 場所（パス）が分かっているときは書き添えます。
「いつものフォルダ」「いま開いているフォルダ」では、読む人はどのフォルダか特定できません。

## 漢語について

**聞き慣れない漢語を、一覧で一律に別の言葉に置き換えません。** 書く人は、その分野で使う語を
文脈に合わせて選び、意味が伝わりにくい語には説明を加えます。**和語のほうがよい、という意味では
ありません。**

一般的な漢語（実施する・確認する・提供する・反映する・追記する・開催する・進捗・設定・履歴・権限 など）は、
そのままで構いません。**固いと感じたときは、言葉を取り替えるのではなく、文を分ける・
だれが何をしたかを書く・長い修飾を分ける、で直してください。** 固さの正体は言葉ではなく、
1文に詰め込まれた情報の多さです。

聞き慣れない漢語を使うときは、文脈で決めます。多くの場合、語を残して、何がどうなるかを説明します。

| 語 | 扱い | 例 |
|---|---|---|
| 具現化する | 何によって実現するのか、具体的な行為（設計書の作成・製品への実装など）を確認して書きます | 構想をもとに設計書を作成する（設計書の作成を指すと確認できたとき） |
| 企図する | 計画する行為なら「計画する」、目標なら「目指す」。文脈に合えば残し、計画の中身を説明します | 新しい市場への参入を計画する |
| 奏功する | 対象と結果を残し、確認できた効果を添えます | 対策が奏功し、問い合わせの件数が半分になった |
| 毀損する | 対象に合う語として使い、必要なら何がどう下がるかを加えます | 信用を毀損する |
| 逼迫する | 何が逼迫するのかを書き、必要なら状態を説明します | 資金繰りが逼迫する（支払いに必要な資金を確保しにくくなる） |
| 恣意的 | 残します。必要なら、何が恣意的かを説明します | 担当者の都合で判断基準を変える、恣意的な運用 |
| 惹起する | 引き起こす | 誤解を引き起こす |
| 勘案する | 考慮する | 繁忙期を考慮して日程を決める |
| 齟齬 | 食い違い／不一致 | 仕様書と画面の表示に食い違いがある |
| 漸次 | 段階的に／少しずつ | 段階的に移行する |
| 喫緊の | 残す、または「早急な対応が必要な」 | 喫緊の課題 |

# ③ AIっぽい文章を避ける

**物差しは2つです。**

> **物差し1　その言葉を削っても、言いたいことは減らないか。**
> 減らないなら、それはAIっぽさです。削ってください。
>
> **物差し2　その文が新しく伝えているのは「書いている対象（出来事・データ・人の判断）」か、
> 「この文章そのもの（どう見えるか・次に何を書くか）」か。**
> 文章そのものについてだけ述べている文は、削ってください（3-4）。

| やめる | なぜ |
|---|---|
| 「本章では〜を扱います」「ここでは〜を見ていきます」「〜について解説します」 | 内容の代わりに、これから何を書くかを言っているだけ |
| 「まとめると」「要するに」（直前の言い換えだけのとき）「〜に他なりません」 | 新しいことを言わずに締めているだけ。数文の議論を短くまとめる合図の「要するに」は残します |
| 「不可欠」「核心的」「鍵となる」「根本的な」「多角的」「包括的」 | 強めているだけで、何がどうなのかを説明していない |
| 「掘り下げる」「深掘りする」「言語化する」「言及する」「触れる」 | 何を書いたかを示さずに終わっている。実際にしたことを書きます |
| 「正面から扱う」「正面から向き合う」 | 姿勢の言葉を削って、動詞だけを残します |
| 「〜ということになります」「〜ということです」（言い換えだけのとき） | 新しい情報を足さずに、文を遠回しにしている |
| 「〜かもしれません」「〜ではないでしょうか」「〜と言えるでしょう」 | 根拠があるのに弱めている（本当に未確定なら残す。1-2を参照） |
| 「非常に」「極めて」「とても」の多用 | 程度ではなく、事実で示す |
| 「重要なのは」「大切なのは」 | 1本に1回まで（1通のメール・1本の記事・1章）。「重要」の中身をその場で書きます |
| 「〜という武器を渡す」「〜という翼を授ける」 | 動作を飾った名詞に置き換えて、格好をつけている。動作をそのまま書きます（「使えるようにする」「教える」） |
| ブログ・記事の本文での箇条書きの羅列 | 項目どうしと、直前の場面との関係が書かれていない。手順書・提案書・チェックリストは対象外です |

**言葉を1つずつ禁じるのではなく、上の物差しで見てください。**
単語だけを禁じると、同じことを別の言い方に置き換えるだけになります。

## 3-1　ダッシュ（`——`）を使わない

**これは言い回しではなく、文字の話です。** AIは日本語を書くときに、英語の書き方を
そのまま持ち込んで、文の途中にダッシュ（`——` `―` `—`）を入れます。日本語の文章では
ほとんど使われない書き方なので、読んだ人に「AIが書いた」と伝わります。

> 直す前：お金を動かすこと ―― あなたの環境に合わせて足します
>
> 直したあと：お金を動かすこと（あなたの環境に合わせて足します）

**地の文・見出し・表題では使いません。** 言い直しや補足を入れたいときは、
括弧に入れるか、句点で2つの文に分けるか、読点でつなぎます。

対象外：フォルダの図に使う罫線（`├─` `└─`）は、形が似ていますがダッシュではありません。
日付や番号をつなぐ半角のハイフン（`2026-09-12`）も、そのまま使います。

## 3-2　ものの動きにたとえた動詞を使わない

AIは、頭の中の働きや、機械の処理を書くときに、**ものが動くようすにたとえた動詞**を
使いがちです。読むと、そこだけ調子が変わって「AIが書いた」と伝わります。

| 直す前 | 直したあと |
|---|---|
| 「問題なし」のほうへ**流れます** | 「問題なし」と**判断してしまいます** |
| 検査を**走らせます** | 検査を**実行します** |
| 記録に**載せます** | 記録に**書きます** |
| ルールに**効きます** | ルールが**適用されます** |

**見分け方：その動詞が、もともと体や物の動きを表す言葉かどうか。**
流れる・走る・回す・叩く・投げる・拾う・落とす・刺さる・効く などが当てはまります。
考えることや、機械の処理には、そのままの言葉（判断する・実行する・記録する）を使います。

**ただし、語源だけで禁止しません。** 業務や技術の分野で定着している組み合わせ
（「引数を渡す」「方針を示す」「色を指定する」）は使います。判定は 3-3 の1問です。

## 3-3　動詞が、その言葉と結びつくかを確かめる

> **その言い方を、その分野の人が実際に使うか。**

使わないなら、使う言い方に直します。**名前が正しくても、動詞が結びついていないと
日本語になりません。**

**1つの名詞に、1つの動詞を決めて対応させないでください。** 同じ名詞でも、作業の中身で動詞が
変わります（資料を作成する／資料に調査結果を記載する／申請書の氏名欄に記入する）。

| 直す前 | 直したあと |
|---|---|
| 変更履歴を**始める** ／ 仕組みを**始める** | 変更履歴の記録を**開始する** ／ 仕組みの運用を**開始する** |
| 資料を**埋める** ／ 資料を**記入する** | 資料を**作成する** ／ 資料に調査結果を**記載する**（申請書などの**欄**に書くときは「氏名欄に**記入する**」） |
| ダイアログが**出る** ／ **出た**窓 | ダイアログが**表示される** ／ **表示された**ダイアログ |
| 控えを**強引に**上書きする | 控えを**上書きする**（「強制的に」は、通常の制約を外して上書きする操作を説明するときだけ添えます） |
| （人に知らせる場面で）情報を**渡す** ／ 色を**渡す** | 情報を**伝える** ／ 方針を**示す** ／ 色を**指定する** |
| ルールが**破れている** | 違反なら「ルールに**違反する**」、守られていないなら「約束を**守っていない**」、対象外なら「このルールは**適用されない**」 |

**「渡す」は、人に何かを知らせる場面では使いません**（情報・指示・方針）。ただし、プログラムに
データを渡すような技術の分野で定着した組み合わせ（「引数を渡す」）は使います。
**「破れる」は物が裂けるときの言葉なので、ルールや約束には使いません。** 違反・不履行・対象外は
意味が違うので、文脈で書き分けます。

ほかの名詞と動詞の組み合わせは、`Japanese_Writing_Rules_使う語.md` にあります。

3-2 とは別のものです。3-2 は、たとえが現実と噛み合っていない場合です。
こちらは、**たとえではないふつうの動詞**が、その言葉の慣用と合っていない場合です。

## 3-4　文章そのものについてだけ述べている文を削る（物差し2）

**削る文の例**（話題がこの文章そのもので、読む人が知りたいことが1つも増えていない）

- 「ここまでだと、概念の説明に見えるでしょう。なので、すぐに例へ戻ります。」
- 「誤解しないでほしいのですが、〜を否定したいわけではありません。」
- 「次は〜を見ていきます。」

**残す文の例**（出来事か、書き手の判断のようすを伝えている）

- 「うまくいっているに違いない、と思っていました。」（思い込み）
- 「今すぐ手を打つほどではありませんが、どこかで整理は要るでしょう。」（判断の保留）

**文章について述べる文でも、残してよい形が4つあります。** ①読む人の反論や誤解を「」で具体的に
書いて答える ②問いを立てて、あとで答える ③読む人へのお願いやおことわり（冒頭と結び）
④例を始める・終える（「〜としましょう」）。

## 3-5　短くするために、伝えるべきことを削らない

**短くて調子がよいことは、残す理由にも、削る理由にもなりません。**
文の調子を作るために、範囲・前提・比べる相手・未確定のことを削るのは、欠落です。

とくに、1枚・1画面に収めようとすると、目的語・主語・理由から先に削りがちです。
**分からなくなるなら、文を削らずに、形（列の幅・行の高さ・枚数）を変えてください。**

## 3-6　つなぎの言葉を確認する

「〜において」「〜という側面から」「〜の観点から」、「さらに」「また」「加えて」の連続、
「〜につながります」「一方で」「しかし」は、使う前に一度確認します。

- **新しい情報を足していないなら、削ります**
- 「〜につながります」は、あいだの理由が書いてあるかを確認します
- 「一方で」「しかし」は、前後が本当に対立しているかを確認します

確認のしかた：**つなぎの言葉をいったん外して読み、文の関係が変わらなければ削ります。**

## 手順書を書くときの4つ（①〜④とは別に、追加で当てはまります）

読む人が**そのとおりに操作する**文書（手順書・マニュアル・社内の作業手順）を書くときは、
次の4つが追加されます。

**1　読む人への約束は、実装を確かめてから書く**

> **その動作をさせる指示が、実際にどこかのファイルに書いてあるか。**

書いていなければ、その約束は成立しません。**書くのをやめるか、先に指示のほうを足してください。**

「〜が確認します」「〜が1件ずつ示します」と書いても、そう振る舞わせる指示がどこにも
なければ、そのとおりには動きません。**読む人は、書いてあるとおりに動くと思って待ちます。**

**2　説明は、読む人がその操作をする場所に置く**

先に書いても、あとに書いても、**操作しているその瞬間に目に入らなければ読まれません。**
大事な注意ほど、手順の最後にまとめず、**その手順の中に置いてください。**
操作に関係しない予告や教訓は、手順のあいだに挟みません。

**3　手順の番号は、大見出しが変わったら1から始める**

同じ大見出しの中では、小見出しや表をまたいでも1に戻しません。AI が報告に使う番号と、
手順書の番号をそろえます。Word などへ変換したら、変換後の番号も確認してください。

**4　操作を指示する手順は、動詞で終えて「。」を付ける**

項目名や部品の名前を示す名詞句には「。」を付けません。同じ一覧の中で、2つを混ぜません。

> 操作の手順：「保存」をクリックします。
>
> 名詞句の一覧：保存先のフォルダ

## このファイルの育て方

- ルールを足すときは、**どこまで当てはまるルールなのかを必ず書いてください**
  （すべての文章か、本文だけか、メールだけか）。範囲を書かないルールは、
  当てはめすぎて、かえって読みにくい文章を作ります
- 同じことを2か所に書かないでください。2か所あると、片方だけ直って食い違います
- 場面ごとに使う語を足すときは、`Japanese_Writing_Rules_使う語.md` に1行足します（このファイルには書きません）
- ルールが増えて読まれなくなるより、少なくて守られるほうが、良い文章が出ます
